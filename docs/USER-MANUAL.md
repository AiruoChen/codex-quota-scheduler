## 1. 第一次使用：照着这条路线走

不用一次读完整本手册。第一次按下面的顺序操作即可：

| 步骤 | 你要做什么 | 做完后应该看到什么 |
| --- | --- | --- |
| 1 | 取得完整 0.3.0 测试包并安装 | 能打开“Codex 任务助手” |
| 2 | 先使用默认模拟环境 | 顶部显示模拟体验，任务列表为空 |
| 3 | 保存一项练习任务 | 任务出现在列表中，但没有执行 |
| 4 | 在本机安装、登录官方 Codex CLI | `codex --version` 能显示版本，登录成功 |
| 5 | 在“设置与帮助”将 `provider` 改为 `codex` | 保存后提示需要重启 |
| 6 | 重启自有后台，点击“查询额度” | 能看到本人账户及新查询的额度 |
| 7 | 创建一项只读任务，先手动执行 | 在运行记录里看到结果 |
| 8 | 准备下一项任务，确认加入队列 | 队列出现对应版本的记录 |
| 9 | 启动调度进程，再点击“恢复派发” | 调度不再暂停，后台按条件等待或执行 |
| 10 | 保持电脑开机、联网且不休眠 | 可以从托盘重新打开窗口查看进度 |

**记住三个区别：保存任务不等于执行；加入队列不等于已经发送；额度显示刷新不等于所有执行条件都满足。**

如果只想看看界面，做到第 3 步即可。模拟环境不会给真实 Codex 发送任务。

<a id="section-2"></a>
## 2. 这个软件能做什么

你可以提前把“让 Codex 做什么”写好。程序读取真实账户额度，在你明确加入队列并恢复派发后，等待合适条件，按顺序把任务交给本机 Codex。

它可以帮助你：

- 查看账户额度、服务端返回的刷新时间和最近查询状态。
- 保存多个任务，检查指令、工作文件夹和文件访问权限。
- 立即运行一项任务，或让已经排队的任务等待额度后执行。
- 查看运行结果、请求取消、核对结果不明的记录。
- 备份个人数据，导入旧项目数据，手动升级客户端。

它不能增加账户额度、绕过周限制，或保证额度一到点就立即执行。是否允许发送，以真实查询、账户状态和其他执行条件为准。它也不是云端定时器：电脑关机或休眠时，本机调度不能继续工作。

### 先认识几个词

| 名称 | 用普通话解释 |
| --- | --- |
| 本客户端 / Codex 任务助手 | 你正在操作的任务管理软件 |
| 官方 Codex CLI | 官方提供的本机程序，负责连接账户和实际处理任务；CLI 可以理解为“通过文字命令操作的程序” |
| 后台服务 | 在本机负责存数据、监控和执行的程序；窗口隐藏后它仍可能运行 |
| 任务 | 一份保存好的工作要求，可以编辑 |
| 队列 | 你明确安排给程序执行的任务列表 |
| 快照 / 版本 | 入队时封存的一份任务副本；之后编辑任务不会修改这份副本 |
| 运行记录 | 某一次执行的状态、指令副本和结果 |
| 待人工核对 | 程序无法确定发生了什么，需要先查清，不能直接当作没执行 |

## 3. 准备与下载安装

### 3.1 需要准备什么

- 一台可运行该测试客户端的 Windows x64 电脑。其他系统和架构尚无本手册对应的安装包。
- 完整安装包或完整便携目录。
- 要真实执行时，需要可用网络、官方 Codex CLI，以及能使用 Codex 的 ChatGPT 账户。
- 一个允许 Codex 查看或修改的项目文件夹。

**仅安装本客户端不要求另装 Node.js 或 npm。** 通过 npm 安装官方 Codex CLI，或自行从源码启动时，才需要相应工具。首次真实接入仍有少量命令步骤，日常任务操作可以在界面完成。

### 3.2 从哪里获取

先查看本仓库的 [Releases 页面](https://github.com/AiruoChen/codex-quota-scheduler/releases)。有与本手册匹配的版本时，下载该版本附件中的 Windows x64 安装包。

如果页面没有安装包，向维护者索取已经验证的测试包。编写本手册时，完整测试包的安装器名称为 `CodexQuotaScheduler-0.3.0-win-x64-setup.exe`。

GitHub 的 **Code → Download ZIP** 下载的是源码，不是安装程序。零基础用户请取得现成安装包；维护者的构建方法在附录 B。

当前测试包未完成正式签名和全部稳定版验收。遇到系统提示时先核对文件来源与维护者提供的校验值；不确定时请维护者协助，不要关闭安全软件或全局降低系统安全设置。

### 3.3 使用安装版

1. 双击取得的 `setup.exe` 安装文件。
2. 按安装向导操作，首次安装通常保留默认位置即可。
3. 完成后，从 Windows 开始菜单打开 Codex 任务助手；如果选择创建了桌面快捷方式，也可以双击它。
4. 等待连接后台。若停留在状态窗口，点击“启动 / 重试连接”。

安装面向当前 Windows 用户，默认程序位置在 `%LOCALAPPDATA%\Programs\CodexQuotaScheduler`。

### 3.4 使用便携版

1. 将维护者提供的整个便携压缩包解压。
2. 打开解压后的文件夹。
3. 双击 `CodexQuotaScheduler.exe`。

请保留同目录的文件和子文件夹。只复制一个 EXE 会导致程序无法运行。便携版默认也把个人数据放在用户数据目录，不是把所有数据放在 EXE 旁边。

### 3.5 怎样确认拿对了版本

打开“后台服务 → 安装与数据迁移…”，查看客户端版本。完整版本的主窗口左侧应有下一节列出的六个页面。

若显示 0.1.0，或缺少本文按钮，请先索取完整包。重新下载同一份旧源码或重复安装旧包，不会补齐后续模块。

## 4. 认识两个窗口和六个页面

客户端有两个用途不同的窗口：

- **主窗口**：日常看额度、编辑任务、查看队列和结果。
- **后台状态窗口**：启动、停止、重启、安全退出，以及备份和数据迁移。可从菜单“后台服务 → 服务状态与通知…”打开。

主窗口的六个入口：

| 页面 | 什么时候打开 |
| --- | --- |
| 运行概览 | 看额度、当前任务和整体状态 |
| 任务管理 | 新建、修改、停用、归档任务 |
| 调度队列 | 加入执行计划后，启动调度、暂停或恢复派发 |
| 运行记录 | 查找每次执行、阅读或复制结果 |
| 异常与恢复 | 处理待核对、断线后遗留状态等问题 |
| 设置与帮助 | 保存连接配置、看日志、导出脱敏诊断 |

主窗口顶部会显示当前数据来源、脱敏账户和连接状态。账户显示被遮挡是正常现象。

“重新连接”只重新建立界面与本地服务的连接；保存配置后的“重启自有后台”在后台服务菜单或状态窗口中操作，两者用途不同。

## 5. 先在模拟环境练习一次

第一次启动默认使用模拟额度和空任务列表。你可以放心练习保存、查看和入队；模拟模式不会执行真实任务。

1. 在文件资源管理器中准备一个练习文件夹。可以放入一份不含私人信息的说明文本。
2. 打开“任务管理”，点击“新建任务”。
3. 按下表填写。

| 表单项 | 练习时怎么填 |
| --- | --- |
| 任务名称 | 第一次练习：阅读项目 |
| 任务 ID | `first-check` |
| 项目目录 | 点击“选择项目文件夹…”并选择刚才的文件夹 |
| 优先级 | 保留 `10` |
| 启用此任务 | 保持勾选 |
| 指令 | 使用下面的示例文字 |
| 文件访问权限 | 只读 |
| 最长运行时间（秒） | 保留 `900`，即 15 分钟 |
| 模型与会话 | 模型留空，保持新建会话 |

示例指令，可以直接复制到“指令”输入框：

```text
请阅读这个文件夹中的说明文件，用中文告诉我：
1. 这个项目主要做什么。
2. 最值得先看的三个文件是什么。
如果文件不足，请说明还缺少哪些信息。
不要修改、删除文件，也不要安装软件。
```

点击“保存任务”。看到列表里出现任务，就完成了保存练习。

你还可以点击“加入队列”，检查预览，再点击“确认加入队列”。这只是在模拟队列中保存一个安排，执行按钮或真实派发仍不可用。

**练习结束后，到调度队列移除这条练习快照。** 切换真实来源前，再检查一次队列，避免把体验时排入的内容带入真实执行。

## 6. 安装并登录官方 Codex

这一步通常只在第一次接入、更换账户或登录失效时需要。已经能在本机终端使用 Codex 的用户，可以先检查版本，再继续使用原安装。

### 6.1 打开 PowerShell

按键盘 **Win + R**，输入 `powershell`，按回车。这会打开一个可以输入文字命令的窗口，通常不需要管理员身份。

下面每个代码框里的命令都可以复制。只复制命令本身，粘贴后按回车；不要复制手册标题或说明。

先运行：

```powershell
codex --version
```

出现 `codex-cli` 和版本号，说明找到了程序。若提示无法识别 `codex`，先按官方 [Codex CLI 安装说明](https://learn.chatgpt.com/docs/codex/cli) 安装；需要可复制的 npm 安装步骤时见附录 B。

### 6.2 登录你的 ChatGPT 账户

运行：

```powershell
codex login
```

按终端提示打开浏览器，并使用你准备给本项目使用的 ChatGPT 账户完成登录。官方登录流程由 Codex 和浏览器处理，本客户端没有内置登录向导。[官方登录说明](https://learn.chatgpt.com/docs/auth)

如果已经登录且账户正确，无需反复登录。需要查看当前登录方式时运行：

```powershell
codex login status
```

本项目的订阅额度读取需要 **ChatGPT 账户登录**。官方 CLI 也支持其他认证方式，但用 API Key 登录不能在本项目中当作 ChatGPT 订阅额度来源。

在你日常运行客户端的同一个 Windows 用户下安装和登录。仅在浏览器登录 ChatGPT，或仅打开官方桌面应用，不能证明本客户端能找到可用的独立 CLI。

完成后回到本客户端。无需把登录文件、密码、验证码或令牌粘贴到任务、配置或聊天里。

<a id="section-7"></a>
## 7. 切换到真实账户

### 7.1 先清理练习安排

到“调度队列”检查练习快照已经移除，派发保持暂停。如调度进程已经开启，先停止调度并等待当前操作结束，再修改配置。

### 7.2 用界面修改来源

1. 打开“设置与帮助”。
2. 在“运行配置”的“配置项”中选择 `provider`。
3. 在“值（JSON 或字符串）”中输入 `codex`，不要输入中文“真实”。
4. 点击“保存配置”。
5. 从“后台服务”菜单打开状态窗口，点击“重启自有后台”。
6. 如出现确认流程，选择等待完成，再按界面提示确认。

重启成功后队列仍会暂停，不会因为改了来源就自动执行。

### 7.3 验证连接

回到“运行概览”，点击“查询额度”。成功时应该满足：

- 顶部不再是模拟体验，账户是你预期使用的账户。
- 显示真实查询时间和额度窗口。
- 没有 CLI 缺失、未登录或协议错误提示。

账户不对时先暂停派发，核对 CLI 登录以及下方的连接目录。额度未知或查询失败时，先处理原因，不通过调低保留阈值来掩盖问题。

### 7.4 提示找不到 Codex 时

如果终端能运行 Codex，但客户端显示 `CODEX_NOT_FOUND`：

1. 安装 CLI 后，先完整退出客户端，再重新打开，让它读取更新后的运行环境。
2. 仍不行，在 PowerShell 运行 `where.exe codex`，查找命令位置。
3. 在“设置与帮助”选择 `codex.executable`，填写找到的可用启动文件完整路径，保存并重启后台。
4. 标准 npm 安装生成的 `codex.cmd` 可以使用；拿不准选哪个文件时，把错误码和路径类型交给维护者核对，不要随意填写脚本。

`codex.home` 通常保留原设置。它指定 Codex 自己的数据和登录目录，不是任务的项目文件夹，也不是本客户端的数据目录。自定义过该项时，必须在同一 Codex 目录下完成登录；不要随便改成一个空文件夹。

## 8. 创建一项真正要做的任务

建议先从“阅读文件并给出建议”的只读任务开始，确认流程正常后再安排文件修改。

在“任务管理 → 新建任务”中填写：

| 项目 | 怎么理解与填写 |
| --- | --- |
| 任务名称 | 给自己看的名称，例如“检查说明文档” |
| 任务 ID | 程序识别任务用的唯一名字，例如 `readme-check`；建议使用英文字母、数字和短横线，保存后不能直接改 ID |
| 项目目录 | Codex 工作的文件夹；优先使用“选择项目文件夹…” |
| 指令 | 写清范围、预期结果，以及允许做哪些操作 |
| 优先级 | 0 至 1000；数值越大，排队时越优先；不确定就填 10 |
| 启用此任务 | 勾选后可作为可执行任务；停用不等于取消当前运行 |
| 文件访问权限 | “只读”用于阅读分析；“允许修改项目目录”用于你明确授权的文件修改 |
| 最长运行时间（秒） | 默认 900 秒；达到时限后会请求中断，不能保证瞬间停止 |
| 模型 | 留空使用本机 Codex 默认；不确定时保持留空 |
| 推理强度 | 保留默认即可，不同模型支持情况可能不同 |
| 会话方式 | 第一次选“新建会话”；只有知道准确会话 ID 时才使用续接 |

指令模板：

```text
目标：我希望你完成什么。
范围：只处理哪些文件或目录。
允许的操作：只读分析，或明确说明允许修改的内容。
要求：需要遵守哪些规则。
完成后：请用中文列出结果、修改内容和验证情况。
遇到不确定事项：请说明原因，不要自行扩大范围。
```

选择允许修改文件时，先为重要项目保留可恢复副本。客户端的数据备份不包含项目文件；取消任务也不会自动撤销已经发生的修改。

检查后点击“保存任务”。**保存只产生任务版本，不会立刻执行。**

<a id="section-9"></a>
## 9. 立即执行一次

适合第一次测试真实流程，或你现在就想让某项任务开始尝试执行。

1. 确认已连接真实账户，项目目录和权限正确。
2. 在“任务管理”找到任务，点击“执行”。
3. 阅读快照预览，核对指令、版本、目录和权限。
4. 点击“确认手动执行”。
5. 打开“运行记录”查看这次运行。

程序仍会检查身份、额度和是否已有任务在执行。手动执行不能绕过限制；同一份数据库同时只允许一个执行者。

如果结果是“等待额度”，这次没有因等待而无限循环。额度恢复后，打开**原运行记录**，核对快照，再点击“手动启动此快照”，避免反复创建新的手动执行记录。

手动执行和自动队列是两种入口。若同一项工作已经排进自动队列，可以在其原记录中“手动启动此快照”；不要又在任务列表点击“执行”创建另一份安排。暂停自动派发也不会禁止你主动点击手动执行。

<a id="section-10"></a>
## 10. 等额度可用后自动执行

### 10.1 把任务加入队列

1. 打开“任务管理”，找到已保存的任务。
2. 点击“加入队列”。
3. 检查快照预览，确认是你要执行的版本。
4. 点击“确认加入队列”。

加入队列保存的是此刻的版本副本。之后修改原任务，排队中的副本不会跟着变化。

### 10.2 启动调度，再恢复派发

1. 打开“调度队列”。
2. 点击“启动调度进程”。启动后仍保持暂停。
3. 检查账户、队列内容和额度状态。
4. 点击“恢复派发”，阅读提示并确认。
5. 查看“后台最近判定”一类的等待原因和队列状态。

默认条件满足时，会按优先级依次执行。数值更大的任务优先；优先级相同时，先入队的先领取。正在运行的任务不会因为加入了更高优先级任务而被抢占。

**恢复派发后，若额度已经可用，任务可能立即开始。** 要等你指定的某个时刻再执行时，请先保持暂停；当前没有“每天几点运行”的图形化定时功能。

### 10.3 两种调度方式

| 配置值 | 含义 | 初次使用建议 |
| --- | --- | --- |
| `available` | 完整查询确认额度可用时，可以领取后续快照并串行执行 | 保留默认 |
| `refresh` | 等新的额度刷新被完整查询确认，再触发一项队列任务；仍须满足其他条件 | 熟悉流程后按需使用 |

在“设置与帮助”修改 `scheduler.trigger`，保存并重启后台后生效。启动或刚建立基线不等于发现了一次新刷新；在 `refresh` 模式下，即使有剩余额度，也可能继续等下一次确认的新刷新。

### 10.4 让它在后台等待

保持电脑开机、联网、不休眠。可以将窗口隐藏到托盘。锁屏、网络切换或休眠唤醒后的实际状态，应重新打开概览确认。

任务成功后不会每次刷新都重复执行。同一任务版本重复入队会返回原有记录；如确实需要安排新一轮，修改并保存成新版本，再明确加入队列。

重启客户端或后台后，重新检查并手动恢复派发。失败、审批或结果不明也可能使队列暂停，先查清原因再恢复。

<a id="section-11"></a>
## 11. 看懂额度和等待原因

“运行概览”显示服务端实际返回的额度窗口。可能看到较短窗口、周窗口等，名称和时长以实际结果为准；不要只盯着“五小时”一个数字。

| 显示内容 | 含义 | 你可以怎么做 |
| --- | --- | --- |
| 额度可用 | 所有相关窗口满足当前规则 | 检查队列、调度是否已启动和恢复 |
| 额度不足 / 已耗尽 | 至少一个相关窗口仍受限 | 等待服务端额度变化 |
| 已达到保留额度阈值 | 剩余比例碰到你设置的保留线 | 等待，或在理解影响后调整保留设置 |
| 额度未知 | 当前没有完整可信的新数据 | 先查询或修复连接 |
| 读数已过期 | 上次结果太旧，或已到服务端边界 | 点击“查询额度”，等待新结果 |
| 缺少额度窗口 | 以前有的窗口本次未返回 | 等完整查询，不能当作无限额度 |
| 账户身份未知 | 账户信息不足以确认执行身份 | 检查登录与 Codex 连接目录 |

默认保留额度为 10%。例如某个相关窗口剩余 10% 时，程序会等待；这是比例阈值，不是“预留十次任务”。任务实际消耗不可由此精确预估。

看到刷新倒计时归零，也仍需查询确认。短窗口刷新而周窗口仍不足时，任务仍会等待。通知说“已确认刷新”，也不代表队列里的任务一定已经执行。

“查询额度”只做完整查询；“开启监控”持续跟踪；这两个操作本身都不表示允许自动派发。停止监控后，旧读数过期会变成未知。

时间通常按界面本地格式显示；导出记录中的时间如以 `Z` 结尾，则是 UTC 时间。核对时留意时区。

<a id="section-12"></a>
## 12. 修改任务与调整队列

### 修改尚未执行的任务

1. 先“暂停派发”，避免操作期间旧快照被领取。
2. 到队列移除旧的、尚未领取的快照。
3. 在任务管理中编辑并保存，生成新版本。
4. 对新版本重新“加入队列”，检查预览。
5. 核对队列后再恢复派发。

如果快照已经被领取，移除可能被拒绝。此时查看实际状态，按取消或异常核对流程处理。

### 几个容易混淆的操作

| 操作 | 实际作用 |
| --- | --- |
| 保存编辑 | 产生新版本；旧快照的指令、目录、权限和优先级不变 |
| 修改优先级 | 新版本重新入队后使用新优先级；不会直接重排旧快照的优先级 |
| 停用 | 当前定义停用，自动领取会检查；不会自动终止当前运行，也不删除旧记录 |
| 归档 | 任务从普通列表隐藏，历史保留；未领取安排会被跳过，当前运行不因此取消 |
| 移除队列记录 | 仅移除未领取的安排，需要确认；旧版本去重记录仍保留 |
| 同版本再次加入 | 返回原记录；即使旧记录已完成或移除，也不会凭空产生新的自动执行 |

保存时提示 `TASK_CONFLICT`，说明其他窗口或操作已经修改了任务。先复制保留自己的草稿，再决定是否“重新加载服务器版本”。重载会确认放弃尚未保存的编辑；关闭客户端不会自动保存草稿。

<a id="section-13"></a>
## 13. 查看结果与运行状态

打开“运行记录”，可以按名称、ID、项目目录或状态查找。点击某条记录，查看详细信息。

| 状态 | 表示什么 | 建议 |
| --- | --- | --- |
| 已排队 | 已保存安排，尚未执行 | 查看调度是否暂停 |
| 等待额度 | 当前额度条件不满足 | 自动队列可继续按规则等待；手动记录可在条件恢复后启动原快照 |
| 执行中 | 本地执行流程已开始，可能正在预检或处理远端回合 | 等待结果；不把该状态单独当作已提交证据 |
| 已完成 | 已确认成功并保存结果 | 阅读输出，核对实际文件或工作成果 |
| 失败 | 本次运行失败 | 看错误原因；存在已提交证据或部分结果时先核对 |
| 待人工核对 | 无法确认结果，或遇到审批、输入等情况 | 按第 15 节处理，不直接重发 |
| 已取消 | 已按当前阶段确认取消 | 仍需检查是否已有文件修改 |

详情中可以看到本次使用的任务版本、项目目录、权限、时间、原会话和准确回合 ID。

点击“查看不可变指令快照”可核对当时发送的内容；“复制指令快照”和“复制输出”分别复制对应文字。“到输出末尾”用于快速查看结尾。

执行中、失败或待核对时的内容可能只是**已保存的部分输出**。没有输出不代表一定没有执行；“已完成”也不代替你对实际文件和工作质量的检查。

若系统拒绝复制，手动选中文字后按 **Ctrl + C**。查看长输出时，程序会尽量保留阅读位置。

<a id="section-14"></a>
## 14. 暂停、取消、关闭和退出

按你的目的选操作：

| 你想做什么 | 该选什么 | 当前任务会怎样 |
| --- | --- | --- |
| 暂时不要接下一项 | 暂停派发 | 当前任务继续 |
| 停止某次任务 | 运行详情 → 请求取消 | 等待远端终止确认 |
| 不看窗口，继续后台工作 | 隐藏到托盘，或托盘可用时关闭窗口 | 当前任务和派发状态保持 |
| 停止自动调度循环 | 停止调度进程 | 该进程的当前执行会被请求停止，并等待结果保存 |
| 停止本客户端管理的后台 | 停止自有后台，按提示等待或请求取消 | 保存结果后停止 |
| 应用刚保存的配置 | 重启自有后台，按提示确认 | 先安全结束旧后台，新后台保持暂停 |
| 完整退出客户端 | 托盘 → 安全退出…，或后台服务 → 退出客户端 | 按归属及等待 / 取消选择安全收尾 |

### 请求取消后

看到“等待取消确认”或“等待准确回合终态”时，说明请求已发出，还不能认定已经停止。网络断开或无法收到终态时，可能进入“待人工核对”。

取消不会把已经修改的文件恢复原样。需要撤销文件修改时，先核对成果，再使用你为项目保留的备份或版本管理。

### 关闭窗口后

托盘可用时，点窗口右上角“×”通常只是隐藏。第一次会出现说明，确认后可继续隐藏。Windows 右下角可能需要点小箭头才能看到图标。

要完整退出，请使用“安全退出…”并等待完成。托盘不可用或状态文件异常时，客户端会保留状态窗口供你处理。

### 如果写着“外部服务”

表示当前后台由别的进程启动，客户端只是连接它。退出客户端通常只断开连接。暂停或明确停止外部服务会影响它的其他连接；拿不准时先找启动它的人，不通过任务管理器随意结束进程。

<a id="section-15"></a>
## 15. 遇到异常时怎么处理

### 最重要的第一步：先暂停，再核对

发现“待人工核对”、网络异常后状态不明，或断电后记录异常时：

1. 保持派发暂停，保存当前错误码和运行 ID。
2. 打开“异常与恢复”，点击“重新检查”。
3. 查看问题说明，再打开对应原运行记录。
4. 按下面的情形处理；不反复点“执行”创建新任务。

### 情形 A：提示旧进程或执行权仍在

程序会区分“仍在运行”“无法确认退出”和“已确认退出”。

- 仍在运行：等待它结束，或从原实例进行安全停止。
- 无法确认：保持记录，不手动删除锁文件或数据库。
- 已确认退出：阅读页面建议，必要时明确选择“显式修复本地遗留状态”。程序还会重验进程状态。

本地修复只处理本地遗留状态，不能证明远端任务已经停止。后台状态窗口中的“核对服务记录…”也不等于已核对任务结果。

### 情形 B：任务结果不明

1. 在待核对卡片点击“查看记录”，核对项目和原始来源。
2. 点击“只读核对”。这一步只查询记录中的原账户、会话和准确回合。
3. 查看“本次后台会话的核对结果”。只读核对成功后，结果不会自动写回成“已完成”。
4. 确实确认终态后，点击“应用已确认结果”，阅读提示并确认。
5. 查看持久化后的运行状态和实际文件；最后再决定是否恢复派发。

无法确认、缺少会话或回合证据、账户不匹配时，保留原记录并请维护者协助。不要用“最新一次会话”猜测原结果。

### 情形 C：需要审批或补充输入

客户端不会自动批准请求，也没有完整的交互审批面板。此时先核对原会话和实际文件状态，再决定如何继续。程序不会为了省事自动同意全部操作。

### “确认已人工核对”是什么意思

这个按钮仅解除该记录对后续调度的阻塞。它不会把任务改成成功，不会取消远端任务，也不会重新发送指令；原记录可能仍显示待核对，队列仍保持暂停。

**不要仅为让按钮变绿或让队列继续而点击它。** 确认前必须已经查清原会话及文件变化；不确定时保留暂停并求助。

<a id="section-16"></a>
## 16. 托盘和通知

在 Windows 右下角找到程序图标，单击或双击打开窗口；右键可看到打开主窗口、服务状态、暂停派发和安全退出等选项。

打开“后台服务 → 服务状态与通知…”：

- “启用系统通知”默认开启。
- “通知完整查询已确认的额度刷新”默认关闭，按需勾选。
- 最近通知最多保留 50 条，可以查看任务结果或异常提示。

通知使用概括文字，不显示任务指令、输出、账户邮箱或项目目录。模拟环境的通知会标明模拟来源。

关闭系统通知后，本地通知历史仍会记录。没有弹窗时，先查看本地记录，再检查 Windows 通知权限、专注模式等设置。“已请求系统显示”不能保证你一定看到了弹窗。

点击通知可尝试打开对应运行或固定页面。数据来源变了、旧记录不可用或后台无法验证时，可能不能跳转；这时手动打开“运行记录”查找准确记录。

<a id="section-17"></a>
## 17. 备份、恢复和搬家

### 17.1 个人数据在哪里

默认位置是 `%APPDATA%\CodexQuotaScheduler`。无需手写完整路径：

1. 打开“后台服务 → 安装与数据迁移…”。
2. 查看当前数据位置。
3. 点击“打开用户数据目录”，用文件资源管理器查看。

如果通过启动参数使用了自定义位置，以界面显示为准。

用户数据包括任务、指令副本、运行记录和备份，应按私人资料保管。不要把整个目录、数据库或完整备份传到公开 GitHub 问题或群聊。

### 17.2 创建一份完整备份

1. 打开“安装与数据迁移”。
2. 阅读并勾选操作范围确认框。
3. 点击“停止自有后台并等待落盘”，等待当前任务与结果保存完成。若当前任务无法正常结束，先按异常流程处理。
4. 点击“创建完整数据备份”。
5. 记下显示的备份目录；复制**整个备份文件夹**到可靠的位置，并确认里面文件齐全。
6. 备份完成后，如需继续使用，点击“启动 / 重试连接”；检查状态后再决定是否启动调度和恢复派发。

完整备份通常含 `config.json`、`state.sqlite`、`tasks.json`、`source-config.json` 和 `backup-manifest.json`。保留清单和所有文件，不单独挑一个数据库文件当作完整备份。

客户端备份不包括你的项目文件，也不复制 Codex 登录凭据。项目和登录需要分别准备。

### 17.3 从备份或旧项目导入

1. 在旧项目安全停止后台和调度，确认不会继续派发。
2. 在目标客户端的数据管理区域停止自有后台，并勾选操作范围确认。
3. 点击“选择旧配置 / 备份并预检…”。
4. 从备份恢复时，选择完整备份文件夹里的 `config.json`；导入旧项目时，选择旧项目实际使用的配置文件。
5. 阅读预览：来源、目标新副本、任务及记录数量、版本、模拟或真实来源。
6. 确认无误后，点击“确认导入新副本并切换（不启动）”。
7. 完成后显式启动后台。检查账户、项目目录、待核对事项和队列，再手动恢复派发。

导入会创建新的数据副本，不把两份数据库合在一起，也不覆盖旧项目。预检十分钟有效；来源变化或预览过期时重新预检。

**旧项目与导入副本不要同时派发同一批任务。** 它们是独立数据库，不能相互阻止重复执行。

### 17.4 换电脑时额外检查

先在新电脑安装客户端和官方 CLI，完成本人登录。项目文件也要单独搬过去。导入保留原路径含义，不会自动替你找到新电脑上的项目。

核对并编辑任务的项目目录后，生成新版本。旧队列快照仍记录旧目录，需要按第 12 节处理后重新入队。旧运行记录作为历史保留；遇到待核对记录先处理，不通过批量重新入队绕过。

### 17.5 切换已有数据配置

停止后台后，在“保留的数据配置”选择目标，点击“切换所选配置（不启动）”。确认账户、目录、队列属于你想使用的那份数据，再显式启动。

导入、切换或升级失败时保留原件和备份。提示新版数据、损坏标记或数据库缺失时，不自行删除文件来强行启动空库。

<a id="section-18"></a>
## 18. 升级和卸载

### 升级

1. 取得维护者提供的、与你数据兼容的新安装包。
2. 打开“后台服务 → 安装与数据迁移…”。
3. 勾选操作范围确认，点击“备份并安全退出，准备升级”。
4. 等待任务结束、备份完成和客户端退出。
5. 运行新安装包。
6. 打开新版，核对数据、账户和待核对事项；队列保持暂停，检查后再恢复。

安装器发现客户端或后台仍在运行时可能拒绝升级，这是为了让原任务先安全收尾。不要通过强杀进程跳过收尾。

当前使用手动升级，没有自动更新或内置开机启动设置。旧客户端也不能直接打开更新版本的数据；需要回退时，请维护者协助选择匹配程序和备份副本。

### 卸载

先安全退出，再从 Windows 已安装应用中卸载，或使用安装目录内的 `Uninstall.exe`。

卸载会保留个人数据、备份、外部项目和 Codex 登录目录。因此，重新安装后仍可能看到旧任务。确实需要删除个人数据时，先检查备份，并由你单独处理明确的数据目录；卸载器不提供一键删除私人资料。

## 19. 常见问题速查

| 遇到的问题 | 先这样处理 |
| --- | --- |
| 下载 ZIP 后没有安装器 | 那通常是源码；索取完整测试包，或请协助者看附录 B |
| 界面缺少本手册里的按钮 | 核对是否为完整 0.3.0；编写时 `main` 仍为 0.1.0 |
| 显示模拟体验，不能执行 | 安装并登录 CLI，将 `provider` 改为 `codex`，保存后重启后台 |
| `CODEX_NOT_FOUND` | 检查安装，重开客户端；必要时填写 `codex.executable` |
| PowerShell 提示脚本被禁止 | 对 npm 使用 `npm.cmd`；标准 npm 安装的 Codex 可尝试 `codex.cmd --version`、`codex.cmd login`；不要全局降低执行策略 |
| `CODEX_AUTH_REQUIRED` | 在相同 Windows 用户和相同 Codex 数据目录下重新登录 |
| `CODEX_AUTH_UNSUPPORTED` | 核对是否使用 ChatGPT 登录；本项目不把 API Key 当作订阅额度 |
| `ACCOUNT_UNKNOWN` / `ACCOUNT_CHANGED` | 暂停，核对账户及连接目录，再重新查询；没有确认身份前不执行 |
| `CODEX_TIMEOUT` / `CODEX_NETWORK_ERROR` | 检查网络、代理和登录；恢复后重新查询。已有运行状态不明时先核对 |
| `CODEX_INCOMPATIBLE` / `CODEX_PROTOCOL_ERROR` | 请维护者核对 CLI 和协议兼容性；数据异常不表示额度恢复 |
| `QUOTA_WAIT` / 等待额度 | 看具体原因：窗口限制、保留线、过期、缺少数据或身份问题 |
| 明明还有额度却不执行 | 检查其他窗口、保留线、调度进程、暂停状态、触发模式及待核对事项 |
| 加入队列后没有动静 | 确认是真实来源；先启动调度进程，再恢复派发 |
| `SCHEDULER_NOT_STARTED` | 在调度队列先点击“启动调度进程” |
| `EXECUTION_BUSY` / `SCHEDULER_BUSY` | 已有执行者或遗留记录；核对当前运行与异常页，不重复启动 |
| `TASK_CONFLICT` | 保留草稿，核对其他修改，再决定是否重新加载服务器版本 |
| 重复入队只有原记录 | 同一版本去重是正常行为；需要新一轮时先保存新版本 |
| “×”关闭后还在运行 | 检查托盘；要退出使用“安全退出…” |
| 请求取消后仍没显示已取消 | 继续等待准确终态；未知时到异常页核对 |
| `RECOVERY_REQUIRED` / `SCHEDULER_NEEDS_ATTENTION` | 按第 15 节检查；不要删除数据库、锁或直接重发 |
| `RUNTIME_INCOMPATIBLE` | 可能连接了旧后台；请维护者安全停止并升级匹配组件 |
| `MANAGEMENT_BUSY` / `MIGRATION_BUSY` | 等当前操作完成；修改配置前先停止调度并等待执行或核对结束 |
| `DESKTOP_DOWNGRADE` | 数据来自更新版本；用匹配或更新客户端，不直接降级写入 |
| `STORAGE_MISSING` / `CONFIG_MISSING_WITH_DATA` / `MIGRATION_STATE_INVALID` | 保留所有原文件和备份，找维护者检查；不要初始化空库覆盖 |
| 升级安装提示正在运行 | 使用“备份并安全退出”，等待后台收尾后再安装 |
| 没有系统通知 | 查看本地通知历史，再检查 Windows 通知设置；任务是否完成以运行记录为准 |
| 看不到或复制不了输出 | 打开准确运行详情，尝试刷新；复制受限时选中文本按 Ctrl + C |

## 20. 日常检查卡与求助方法

### 每次准备自动执行前

- 顶部账户是本人预期的真实账户。
- 额度刚查询过，且所有相关窗口满足条件。
- 项目目录、权限、指令和队列版本正确。
- 调度进程已启动，没有未处理的待核对事项。
- 确实准备开始后，再点击“恢复派发”。

### 暂时离开电脑前

- 想继续工作：保持开机、联网、不休眠，并确认客户端留在托盘。
- 暂时不要接新任务：暂停派发，当前任务可继续完成。
- 准备关机或升级：安全等待当前任务结束并保存结果；必要时先备份。

### 怎么向维护者求助

在“设置与帮助”点击“导出诊断 JSON”。导出内容经过脱敏，主要是运行环境、连接状态和数量，不含任务正文或完整个人路径；分享前仍先打开检查。

可以复制下面的模板，填好后发给协助者：

```text
客户端版本：
Windows 版本及系统类型：
我点了哪个页面、哪个按钮：
原本希望发生什么：
实际显示的状态或错误码：
问题是否发生在执行、取消、断网、重启或升级之后：
已尝试哪些操作：
能否提供检查后的脱敏诊断文件：
```

不要公开密码、登录令牌、验证码、完整登录文件、数据库、私人指令或完整备份。截图里出现个人路径、账户或输出时，先遮挡后分享。

## 附录 A. 需要时再看的配置表

初次使用只需要先设置 `provider`；程序找不到 CLI 时再设置 `codex.executable`。其余通常保留默认。

所有设置都在“设置与帮助 → 运行配置”中，**一次选择一个配置项，填写值，点击保存；重启后台后生效**。不要把整个表粘进一个输入框。

| 配置项 | 默认或示例值 | 含义 |
| --- | --- | --- |
| `provider` | `mock`；真实使用填 `codex` | 模拟或真实来源 |
| `reservePercent` | `10` | 相关窗口的保留百分比 |
| `pollIntervalMs` | `60000` | 通常查询间隔约 1 分钟；出错等情况会按规则调整 |
| `quotaMaxAgeMs` | `120000` | 读数最多有效约 2 分钟，也会受服务端边界限制 |
| `scheduler.trigger` | `available` 或 `refresh` | 额度可用即派发，或等待确认的新刷新 |
| `codex.executable` | `codex`，或可用启动文件完整路径 | 去哪里找官方 Codex |
| `codex.args` | `[]` | 启动器的额外参数列表；通常不用改 |
| `codex.home` | 通常不设置 | Codex 登录与数据目录；不是项目目录 |
| `codex.requestTimeoutMs` | `15000` | 单次请求等待约 15 秒 |
| `codex.shutdownTimeoutMs` | `1000` | 子进程关闭各阶段的等待设置 |
| `limitId` | `codex` | 使用哪个额度桶；普通用户保持默认 |
| `tasksFile` | 保留当前值 | 首次导入任务清单的位置；日常任务以数据库为准 |
| `storage.databasePath` | 保留当前值 | 当前数据库位置；迁移请使用数据管理入口 |

`ms` 是毫秒：1000 毫秒 = 1 秒。这里的数值字段直接填数字，字符串字段填写对应文字或路径。需要特殊参数或自定义 Codex 目录时，请协助者核对，不在配置中填写密码或令牌。

网页方式没有桌面托盘、原生目录选择和安装迁移窗口。需要统一已有数据时，按明确配置选择或导入副本流程操作，不同时运行两份会重复派发的队列。
