# 续接原会话的明确授权

日期：2026-10-27。适用于包含此功能的开发客户端，程序版本暂为 0.3.0。它保留原会话上下文，使用用户为当前任务版本明确选择的权限，不宣称完整继承原会话的有效权限。

## 操作步骤

1. 安全停止旧后台并退出旧客户端，再打开新版。
2. 新建或编辑任务，选“继续已有会话”，先选项目，再按名称选会话。
3. 核对自动读取的实际目录；它不能手动覆盖。目录和项目下拉框只是定位会话，不会授予文件权限。
4. 在“文件访问权限”选只读或写入。写入时，从读取到的目录中勾选可写文件夹，必须包含实际工作目录；不自动勾选整个项目，也不使用公共父目录替代多个文件夹。
5. 确认读取范围，并勾选“为此任务版本明确授权”。当前本机协议只能提供本机文件读取范围，不能把读取限定到这些项目文件夹；只读也需要确认。若不同意，请不授权。
6. 保存任务。保存不恢复会话，不发送指令。另行预览执行或入队后，才会使用已保存快照开始续接。编辑时必须再次确认；旧队列快照不会随编辑改变。

网络始终关闭；额外审批和输入请求不会自动同意。Codex 可能把所选权限保存成该会话后续默认设置。避免同时在官方客户端向同一会话发送消息。

## 校验与持久化

- 授权预览只用 thread/read、project/read、configRequirements/read 及账户只读查询；官方目录或经校验的明确桌面关联仅提供可选文件夹，不自动给予写权限。
- 后台重新读取环境，不接受浏览器伪造的 environment 或“已验证”标志。上下文摘要绑定账户／连接、准确会话、目录／关联文件夹、CLI 版本及可选沙箱；变化后必须重新确认。
- 任务的 environment 增加可选 resumeAuthorization；原 permissionsVerified 仍为 false。授权随任务版本、运行快照和本地备份保存，不修改旧历史，不需要新建或清空数据库。任务创建请求的重复确认结果稳定，幂等标识不会因当前时间改变。
- 写入范围使用绝对且已解析的准确目录，须来自预览候选；拒绝未确认目录、目录链接重定向和缺少实际工作目录的写入授权。网络关闭，on-request 审批及 user 审批接收方固定。
- 执行前在互斥执行权内重查账户、来源、CLI、目录和管理策略，再使用快照中的配置恢复准确会话。恢复响应必须确认实际工作目录、运行根目录、写入根、临时目录限制、网络和审批方式一致。缺字段、未知策略或范围扩大时停止，保留 needs_attention，且不发送 turn/start 或自动重试。
- 本模式仅执行于本机。恢复响应若返回已选中的外部环境仍阻断；若 environments 为 null（协议定义为未提供元数据），须从本次准确 CLI 生成的 schema 确认空数组可禁用环境访问，才允许继续，并在 turn/start 显式发送 environments: []。不支持生成、语义未知、字段缺失或格式异常时阻断。其他权限仍逐项核验；不把 null 当成“已知没有外部环境”。
- 手动和自动调度共用执行器；自动调度仍初始暂停，只有显式入队的版本可执行。额度中断续接若沿用该授权，也必须重新通过相同检查。
- 审批仍走原有人工核对流程；本功能不是“允许所有后续操作”。固定事件只记录策略标志及文件夹数量，不输出原始错误、个人目录、指令或凭据。

## 兼容边界

已核对本机 CLI 0.164.0-alpha.11.1 的完整实验 schema，及真实只读 configRequirements/read。该版本的 thread/read 不返回完整有效权限，thread/resume 响应则有 sandbox、approvalPolicy、approvalsReviewer 和 runtimeWorkspaceRoots。本适配使用明确的新权限及恢复响应核验；绝不把未知继承权限直接标成已验证。

当前支持 read-only、workspace-write 的已知旧沙箱格式。写入模式通过本次恢复配置禁用网络、排除系统临时目录写入，并传递精确可写根。管理策略禁止这些设置，或强制命名权限配置时阻断；不修改用户全局配置，不自动切到完全访问。CLI 升级、账户或关键目录变化后需要重新授权。远程环境、完整权限继承和官方无文件夹项目仍待支持。

官方依据：[OpenAI App Server](https://learn.chatgpt.com/docs/app-server)、[权限配置](https://learn.chatgpt.com/docs/permissions)。文档比本机 CLI 新时，以本机生成的 schema 和实际响应核验为准；不能把新版字段强行发送给旧版本。

## 验证范围

隔离协议测试覆盖读取／写入续接、授权持久化及快照保留、未确认／过期上下文／额外目录阻断、管理策略变化、服务端实际权限扩大，以及审批不自动同意。GUI 回归覆盖默认不勾选、无授权不能保存、修改权限清除确认和明确保存不执行。

真实环境仅做只读版本、策略、目录和界面检查，不恢复或重发用户原会话任务。模拟恢复成功不能作为真实恢复已经成功的证据；旧 RPC -32600 的具体拒绝原因仍未确认。完整真实恢复／发送验收需另行针对明确任务进行。

本次 check、327 项测试、demo、手册同步与打包桌面回归通过。真实只读打包界面确认项目下会话仍可选、授权预览可用、读取与写入确认均默认未勾选，原任务、运行、执行权及派发状态未变，真实提交为 0。完整跨平台、安装迁移与短时稳定性以当前提交的 CI 结果为准。

## CODEX_AUTHORIZATION_MISMATCH 排查

这个错误表示权限核验没有通过；可能是真实不一致，也可能是信息未知或读取失败。旧版只保存通用错误，无法还原当时具体失败的字段。不能仅凭这个错误认定账户没有权限，也不能保证重新勾选授权就能解决。

本次只读检查确认原报错记录没有 submission_started 或准确回合，当前 CLI 版本、账户及实际目录可核对。已确认一处兼容缺陷：协议允许环境元数据返回 null，旧版却要求返回空数组。原 thread/resume 响应未保存，因此不能确认这是原运行唯一的失败项。修复按上文的准确本机协议验证加显式禁用方式兼容，不扩大本机写入、网络或审批权限。

新版会在错误和 resume_authorization_mismatch 审计事件中指出固定检查项，例如 approval_policy、approval_reviewer、runtime_roots、writable_roots、temporary_writes、network_access、environment_unknown。只保存固定分类、版本及协议核验布尔值；未知异常归 verification_unavailable，不保存原始错误、返回内容、指令、凭据或完整私人路径。

1. 先保持派发暂停，安全停止实际旧后台并退出旧客户端，再打开修复版。
2. 核对原记录和官方会话；缺少准确回合时不能通过“应用已确认结果”猜测回合。只有确实人工核对后，才使用异常页“确认已人工核对”解除阻塞；原状态仍保留，队列不会自行恢复。
3. 编辑任务，刷新会话环境，重新核对目录及授权。保存产生新版本，不修改原运行或旧队列快照。
4. 先使用独立测试会话按下一节验证一次。若仍失败，提供错误中的“检查项”，无需提供指令、原始日志或私人目录。

维护者本阶段只进行了协议替身与真实只读检查，没有重新恢复或重发用户的原会话任务；真实恢复成功仍需用户明确执行后确认。

## 用户首次真实验证

建议先在官方 Codex 新建一个专用测试会话，不使用正在处理工作的原会话。在本工具选择这个测试会话，使用只读权限，并在接受读取范围后明确授权。指令可写：“请仅回复‘续接验收通过’，不要调用工具或修改任何文件。”保存后只做一次手动执行，查看运行记录是否成功、返回的会话是否准确，以及官方客户端能否看到该回复。此步骤会消耗真实额度并增加一条聊天记录，由用户决定执行。

首次验证期间保持自动派发暂停。成功后再为需要继续的原会话保存新的任务与明确授权；若返回权限不一致或待核对，先检查记录，不自动重复发送，也不扩大权限来消除错误。
