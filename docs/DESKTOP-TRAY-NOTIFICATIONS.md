# 托盘与通知

日期：2026-10-26。已实现桌面托盘、关闭后后台运行、通知偏好、本地记录及准确页面定位。
当前验证平台为 Windows x64；安装器、签名、开机启动、退出后的通知冷启动及静默时段仍待开发。

## 使用方法

关闭主窗口或状态窗口会隐藏到托盘，后台、当前任务和队列保持原状态。第一次关闭会显示说明，点击“知道了，隐藏到托盘”即可继续后台运行。
托盘单击或双击可打开窗口；右键菜单提供打开主窗口、服务状态与通知记录、暂停派发、通知开关和安全退出。
托盘不可用或桌面状态文件无法读取时会保留状态窗口，供用户继续保留窗口或显式安全退出，不能悄悄留下无法操作的后台。

“暂停派发”只停止领取后续队列项，当前任务继续。连接外部服务时菜单明确显示“暂停外部服务派发”，此操作影响该服务；关闭窗口本身不改变外部服务。
“安全退出”沿用既有等待/取消流程：活动任务可选择留在托盘、等待完成后退出或请求取消后退出。停止已经开始后不能撤销为继续派发。
取消必须等待准确回合终态；未确认仍保留 needs_attention，不会宣称已取消或自动重发。外部服务默认只断开，停止它仍需单独确认。

在菜单“后台服务 → 服务状态与通知…”或托盘的“服务状态与通知记录”中查看最近 50 条记录并修改偏好。
系统通知默认开启；“通知已确认的额度刷新”默认关闭。关闭系统通知只影响显示请求，本地记录继续保存。

| 事件 | 通知条件 |
| --- | --- |
| 任务成功、失败、确认取消、需要人工核对 | 对应结果已持久化；首次连接不集中弹出旧终态 |
| 已有待核对事项 | 首次连接给出一次概括提示，不逐条轰炸 |
| 登录不可用 | 后台明确返回 CODEX_AUTH_REQUIRED，持续同一故障不重复提醒 |
| 服务连接或额度查询持续失败 | 连续三次失败后提示一次；验证恢复后提示一次 |
| 额度窗口刷新（可选） | 现账户的新鲜完整查询及持久化刷新事件确认，不能由倒计时生成 |

额度刷新和是否允许执行分别判定：其他窗口仍受限时也可能确认某个窗口刷新。过期快照、账户切换前的事件及查询失败不能触发刷新通知。
正常轮询和百分比变化不会提醒；每批最多请求三条原生通知，其他变化仅保留本地记录。模拟来源的通知明确标记“模拟环境”。

通知正文只使用固定概括文案，不显示任务名称、指令、输出、邮箱、个人目录或远端原始错误。
点击系统通知或本地记录时，主进程验证当前服务实例和数据来源，再打开准确运行或固定概览/异常页面。
来源变更、记录已淘汰或服务不可验证时拒绝跳转，不猜测最新任务，不自动启动、重启或修复后台。

## 模块与持久化

- `domain/notifications.ts`：可注入时间的纯通知策略、故障合并、固定文案及事件类型。
- `storage/desktop-feed.ts`：在同步事务中投影已落盘事件；每个流每次最多读取 128 条，以准确运行和终态选取唯一来源，重复修复不重报旧结果。
- `management/service.ts` 与 `adapters/http/desktop-protocol.ts`：只读脱敏事件接口、固定暂停接口和实例校验；使用运行控制密钥，不向管理页面提供通用权限。
- `desktop/notification-store.ts`：校验、串行更新、独占锁、有效备份与原子替换；检查点、去重标识、偏好和通知记录一起保存。
- `desktop/notifications.ts`、`desktop/visibility.ts`：组合持久化、系统显示端口和窗口关闭策略，不依赖 Electron。
- `adapters/electron/tray.ts`、`notifications.ts`：原生图标、固定菜单、系统通知和受限点击回调；`desktop/main.ts` 负责装配。

事件由桌面主进程定期读取，独立于管理页是否显示。读取事件不会派发任务；通知偏好也不改变额度或队列规则。
数据库迁移 7 仅增加稳定的数据源身份，不清空或重建历史。
用户数据目录中的 `desktop-state.json` 保存偏好、游标、最多 512 个近期去重标识和 50 条脱敏记录，写入时维护有效 `.bak`。
文件损坏时保留原文件并报错，不自动用空状态覆盖。该文件、备份和数据库都属于私人数据，不进入 Git 或便携包。

通知记录在请求系统显示前落盘。系统显示结果不明或进程中途退出时不会盲目重播，因此不能保证每条提示都被看到。
“已请求系统显示”仅表示已发起请求；系统禁用通知、专注助手、权限或未签名便携程序的注册情况仍可能影响实际显示。
系统回报失败或不支持时记录对应状态，仍可在客户端查看。当前不提供应用退出后的通知冷启动。
来源身份包含当前完整配置；更换配置后，旧记录可能需要返回原配置才能打开。

## 验证与边界

提交前运行 `npm run check`、`npm test`、`npm run demo`。通知测试使用可注入时间、本机模拟数据库及假显示通道，覆盖故障合并、重启去重、原子保存、损坏文件、系统禁用、准确跳转和刷新新鲜度。
开发版和便携版 smoke 使用 Windows WM_CLOSE 关闭准确的自有进程窗口，验证首次说明、隐藏后后台 PID 不变、通知偏好落盘、后台记录终态、脱敏及点击定位。
生命周期 smoke 新增第七个场景：协议替身任务在隐藏期间完成，准确记录一次提交且没有中断，再定位原运行并安全退出。
所有自动验收使用本机协议替身和模拟数据，没有提交真实账户任务。

本机结果：228 项回归、开发版/便携版 GUI 与七个生命周期场景通过，页面脚本异常为 0。
这些检查不等于人工确认 Windows 通知中心的实际展示、系统托盘溢出区交互、干净机器安装或连续 24 小时稳定性；后续发布验收仍需覆盖。
原生接口依据：[Electron Tray](https://www.electronjs.org/docs/latest/api/tray)、[Notification](https://www.electronjs.org/docs/latest/api/notification)、[BrowserWindow close](https://www.electronjs.org/docs/latest/api/browser-window#event-close)。
