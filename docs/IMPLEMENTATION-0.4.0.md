# 任务体验与额度续接实施说明

日期：2026-10-27。本文描述开发分支中的代码，不代表已更新安装版或完成正式发布。程序仍为 0.3.0；完整 0.4.0 验收尚未完成。

## 已实现的入口

- 新建任务自动生成后台 UUID；创建请求标识只用于幂等去重，任务名称可编辑，旧 ID／版本／归档／运行关联保持不变。
- 模型与推理强度来自当前 Codex 目录，保存真实 wire model 标识；分页、来源和账户变更经过校验，执行前重新检查所选模型，不替换失效模型。
- 官方项目 → Codex 会话两级选择，续接默认提供“全部会话”。项目筛选兼容桌面端待迁移的旧关联：读取明确会话归属及新旧项目 ID 映射，再与当前接口返回的项目／会话核对；标注“桌面项目关联”。没有明确证据的归属保持未知，空结果可显式切回全部，不按目录推断归属。选择器刷新只读元数据，不创建、恢复或中断远端会话。
- 新会话可选本地文件夹、官方项目或无项目。官方项目没有主目录标识时，由用户确认本次工作目录；多个关联文件夹分别展示，写入范围明确勾选。工作区写入模式必须明确包含本次工作目录，网络保持关闭。
- 无项目只读会话使用后台管理的本地工作区，不强制业务目录，也不伪造官方项目。保存任务不提前创建 Codex 会话。
- 任务列表默认按创建时间倒序，服务端先筛选和排序再分页；同一时刻按任务 ID 稳定排序。编辑不修改创建时间，不改变派发优先级和 FIFO；偏好按本地配置范围保存到本地数据库，可跨后台端口更换与重启恢复。损坏的时间数据报告存储错误，不伪造日期。
- 设置页独立修改五小时／周保留线，范围 0～100%，最多一位小数，两项整体原子保存并检查配置 revision。旧统一 `reservePercent` 作为缺失值及其他时长窗口的后备值。按服务端窗口时长匹配，不按 primary／secondary 猜测。保存后安全重启生效，桌面后台保持暂停。

## 额度中断续接

每项任务默认关闭，可显式勾选并设置最多 0～20 次，默认 3 次。只有以下证据同时存在时才建计划：准确回合的失败终态包含明确的 `usageLimitExceeded`，完整真实查询显示窗口确实耗尽，身份、来源和服务端重置时间均已确认。

原失败回合及部分输出不改写；事务内一并保存终态、证据、子运行、队列位置和去重关联。每个父运行至多一个子运行，后续始终使用根运行的原始指令快照，再追加两个换行和“请继续这个被截断的任务”，不会重复叠加后缀，也不受后来编辑的指令影响。实际模型被固定，权限保持原快照。

只有完整新查询证明所有已耗尽窗口的服务端边界推进，且全部窗口高于当前保留线，才可领取。子运行与普通队列共用优先级、FIFO 和唯一执行权；领取和刷新触发消费在同一事务完成。手动执行产生等待计划，不会自动开启调度进程或恢复派发。

执行前核对已记录来源／账户／实际目录，并只读检查准确父回合仍是最近失败回合；发现活动会话、外部新回合或证据缺失时停止自动执行。普通限流、超时、网络断开、提交不明、审批／输入请求、重试中间错误、额度归零后最终成功，均不产生自动重发。提交不明保留 `needs_attention`。

运行详情显示根运行、父运行、父回合和续接次数，可“停止此续接链”。这会取消尚未领取的子记录；已运行回合仍需单独请求取消并等待准确终态。桌面重启保持暂停，进程遗留执行权不自动释放。

## 能力限制及验证范围

本机 CLI `0.164.0-alpha.11.1` 的 `generate-json-schema --experimental` 与真实只读查询确认官方项目 ID／名称／多文件夹。项目接口仍属实验协议；不支持时直接报告。实际桌面状态明确标记项目已迁移，但会话归属尚未迁移，所以接口 `projectId:null` 不足以还原侧栏分组。

`sidebar-state` 适配器只读当前连接准确 CodexHome 下的 `.codex-global-state.json`，仅接受确认过的 v1 待迁移格式；提取本地主机映射、明确项目／会话 ID、待迁移和未分配标识。自定义启动参数、不同 SQLite 来源、未知格式、链接及超限文件不启用兼容，绝不扫描其他账户或目录。读取上限 8 MiB，不返回无关状态或原始错误。该文件格式不是公开稳定 API，未来变化会安全降级。

`sidebar-projects` 仅对当前接口返回的会话与有效项目建立显示关联：非空协议归属优先；旧关联需当前 home 映射、local 主机、待迁移标识及一一对应 ID 同时成立，冲突或缺失保持未知。查询前后核对账户和关联版本，分页绑定来源、项目筛选及关联版本，空页最多连续扫描 10 页后保留下一页。关联更新时要求重读第一页。

显示关联不改写原始 `projectId`、目录或权限；`sidebarProject` 仅供名称和关联文件夹展示。不会写入桌面状态、设置迁移完成、修改远端项目归属或运行会话。迁移完成后回到协议数据；兼容不可用时仍可查看全部会话。

未加载原生会话的只读元数据没有完整有效权限：`environments` 可为空，不能据 `cwd` 或项目文件夹推断授权。未明确授权时仍报告 `CODEX_ENVIRONMENT_UNVERIFIED`；现可通过新增的[续接明确授权](RESUME-AUTHORIZATION.md)选择本任务采用的权限。独立 `resumeAuthorization` 记录准确会话、上下文、CLI 版本及固定策略，原生 `permissionsVerified` 仍为 false；不能把显式新授权当作完整继承原权限。无文件夹官方项目、跨设备／远程环境也未完成支持，U04 不标为完成。

本阶段验证只使用隔离数据库、可注入时钟、协议替身及真实只读目录查询。没有恢复或重发原会话，没有提交真实任务；原先 `thread/resume` 的通用 -32600 具体原因仍未知。不能将模拟成功当成真实恢复成功或完整 0.4.0 发布验收。

初次需求实现已完成模拟 GUI／托盘／重启及 8 项生命周期验收。此次桌面关联修复通过规范检查、320 项测试、demo 和隔离打包桌面回归；真实只读查询在当时 12 个项目、46 个会话中确认 23 个旧会话可匹配到 9 个项目，打包界面选定项目准确显示对应的 6 个会话。原桌面状态文件及任务、运行、执行权、派发配置和队列记录前后未变，真实任务提交为 0。数字是当时本机验证样本，不是固定配置。完整跨平台与安装验收结果以该提交的 CI 为准。

## 验证方法

1. 运行 `npm.cmd run check`、`npm.cmd test`、`npm.cmd run demo`，以及 `npm.cmd run smoke:desktop`。
2. 模拟客户端新建任务时只填名称、文件夹和指令，确认生成固定 UUID；切换时间排序，检查分页与编辑后位置。
3. 设置页整体保存两项保留线，检查“已保存／当前生效”差异，安全重启并确认队列暂停。并发写入须返回 `CONFIG_CONFLICT`，不能覆盖另一份修改。
4. 真实账户只读刷新模型、项目、会话及授权预览，核对来源一致；不得为了验证选择器点击执行。既无完整权限证据、也无明确授权时必须保持阻断。
5. 使用 `tests/continuation.test.ts` 验证耗尽证据、窗口重置、周额度、后缀、重复事件、次数上限、停止、原始快照、互斥、外部回合冲突、提交不明及事务写入失败。

数据库模式新增到 9，保留原表与历史；升级前安全停止旧后台并备份，禁止让活动旧进程跨模式写入。新增导入白名单只允许本项目固定表和准确的派发视图，其他视图／触发器仍拒绝。
