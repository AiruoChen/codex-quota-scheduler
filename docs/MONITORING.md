# 额度监控与刷新识别

## 使用

初始化个人配置后：

```powershell
npm.cmd run build
npm.cmd start -- config set provider codex
npm.cmd start -- monitor watch
```

watch 在前台持续运行，Ctrl+C 或 SIGTERM 停止；每次采样在 stdout 输出一行 JSON，包含 state 和本轮新增 events。
可用 `monitor watch --samples 2` 限制本次采样次数，成功或失败的查询均计数。
停止会回收连接、子进程和订阅；等待或查询可以取消，不会为了退出再发一次查询。

```powershell
npm.cmd start -- monitor sample
npm.cmd start -- monitor status
npm.cmd start -- monitor events
```

sample 查询一次并保存检查点；status/events 只读本地数据库，不连接 Codex。
首次 status 为 null。status 对历史快照重新检查有效期，不能把上次 available 当作当前可用。
sample 查询错误会保存原因并以 1 退出；额度耗尽属于正常采样结果。
watch 遇到查询错误会继续退避，正常停止退出码为 0；存储损坏、保存失败或输出回调错误会停止并报错。
所有命令支持 --config。mock 来源会明确保留 source=mock，且不会执行任务。
monitor 命令不导入、启动或取消任务；自动队列使用独立的 scheduler 命令，见 SCHEDULING.md。

## 查询与恢复

- 常规间隔使用 pollIntervalMs，默认示例为 60 秒。配置变更后重启监控生效。
- account/updated、account/rateLimits/updated 通知提示重读账户及完整额度；不使用通知中的局部窗口替代全量快照。
- 相同通知合并，通知触发的连续查询至少间隔一秒；周期轮询仍会进行，不依赖通知必达。
- 服务端预计 resetsAt 可把下一次查询提前到边界后一秒；不会在本地直接修改额度。
- 失败后按常规间隔的 1、2、4 倍指数退避，上限为 5 分钟与常规间隔中的较大值；通知不能绕过失败退避。
- 连接退出后下一次采样重建连接；登录失效或协议不兼容也保留错误代码并有限频率重试，不自动登录或同意请求。
- 等待期间检测定时器延迟及系统时钟回退。睡眠唤醒或明显时间跳变后立即重新查询，再解释状态。

连接复用时，每次读取额度前后分别查询 account/read；账户字段不一致则丢弃整份快照。
CLI 可能在查询中重复发送相同套餐的 account/updated，这只作为提示，不能单独认定切换了账户。
未知来源身份不会生成真实刷新事件；真实来源的邮箱和工作区 ID 均未知时，可用性保守地记为 unknown。
现有接口不提供跨客户端原子账户快照，不能保证识别两次账户查询之间极短暂的切换再切回。

## 刷新规则

首次读取建立 baseline，不发 quota_reset。只有可比较的相邻观察证据足够时才确认窗口刷新：

1. 来源、可识别账户、工作区及套餐一致。
2. 额度桶 ID、窗口槽和实际窗口时长一致。
3. 新快照新鲜且未乱序，窗口比例已知。
4. 旧的已知重置时间已到，新返回的重置时间向前推进，并且仍在新快照的未来。

不写死五小时或周窗口。每个桶/窗口独立比较，不累加桶间额度；缺失时长、未知比例或没有边界证据均不补造刷新。
比例下降但边界未推进，不产生刷新；比例下降仍可使 availability_changed 表示额度重新可用。
若新边界提前移动，只更新比较基线，不把它解释为自然周期刷新；这可能保守地漏掉提前人工重置。
本工具不消费重置奖励。无法获知进程停止期间发生过多少次刷新，也不会补造中间事件。

已知窗口暂时缺失时保留旧边界；特别是周窗口消失，不能因此放行。
边界回退保留较新的比较基线；账户/套餐/来源变化、窗口时长变化或时钟回退重新建立比较依据，避免串错周期。
服务器仍返回已到期的旧边界时，状态保持 unknown，等待之后的新快照。
没有返回 resetsAt 的新鲜窗口可以参与比例判断，但不能生成周期刷新事件。

## 刷新与可用性

quota_reset 表示某个窗口观察到新周期，不意味着整个账户已可执行。
state.availability 包含 available、blocked、unknown 和具体 reason，按照配置 limitId 检查其所有相关窗口：

- 任一窗口耗尽、服务端 reachedType 存在或达到 reservePercent，继续阻塞。
- 缺少数据、已知窗口消失、读失败、过期或未来快照，不能放行。
- 五小时窗口刷新而周额度仍耗尽时，可以记录刷新事件，但状态仍是 blocked。

事件还包括 baseline、identity_changed、clock_changed、availability_changed、read_error、read_recovered。
相同错误不会每轮写一次事件；重复快照不重复写刷新。state.revision 和 fetchedAt 仍随有效观察更新。
返回的 nextPollAt 是当前进程的查询计划，不代表后台服务已经启动。

## 持久化与隔离

数据库 schema 4 为监控新增检查点、事件及刷新去重键，升级不改变旧任务/执行记录。
来源、连接位置及额度策略形成独立流；修改 provider、limitId、保留阈值或新鲜度策略后使用新流。
pollIntervalMs 调整不会清除已有检查点。账户身份变化在同一流内记录，但重新建立窗口基线。

识别、事件、去重标识和检查点在同一 SQLite 事务中保存；任一步失败整体回滚。
重启后继续旧检查点。事务中重新读取检查点，多个监控进程不能通过并发读写重复保存同一刷新。
每个流的事件明细保留最近 1000 条，刷新去重键单独长期保留；清理明细不会重新发出相同刷新。
自动调度使用独立的持久化游标消费刷新事件；原始监控事件只表示额度观察，实际启动仍以运行记录和执行事件为准。

快照和账户信息只写入本地 SQLite；错误事件仅保存稳定代码，不保存原始 RPC 错误或凭据。
配置和个人数据请继续使用被忽略的 config/local.json、.local、.runtime。
数据库是 :memory: 时仅本进程保留状态。当前不安装系统服务或开机启动项。

指数退避、通知风暴、断线重连、取消、事务回滚，以及独立 CLI 状态读取。
2026-10-20 在 Windows / Codex CLI 0.163.0-alpha.10.2 / Plus 账户上完成两次真实只读采样：
返回 300 和 10080 分钟窗口，检查点持续保存，第二次未产生重复刷新事件。
自然刷新使用模拟时钟序列验证；真实验收未等待完整周期，也未消费额度重置奖励或发送任务。
