# 额度查询一直显示“未知”

## 本次已确认的原因

在本机 CLI `0.164.0-alpha.11.1` 上，账户与 `account/rateLimits/read` 只读查询正常。完整查询返回的 5 小时和周窗口刷新时间均比历史检查点早 1 秒。旧版把任何回退都当作不可信数据，保存“额度未知”，界面因此隐藏正常返回的百分比。

这是刷新时间比较问题，和续接会话的授权无关。此次检查没有执行、恢复或重发真实会话。

官方协议将 `resetsAt` 定义为服务端 Unix 秒时间戳，见 [Codex App Server](https://learn.chatgpt.com/docs/app-server)。官方文档没有承诺时间差上限；本次仅对本机明确观察到的 1 秒差异作有限兼容，不扩大到其他时间范围。

## 普通用户如何更新

1. 先暂停派发，等待正在运行的任务结束；结果不明的任务保留待核对状态。
2. 在客户端后台控制中安全停止实际后台，再退出客户端。仅关闭窗口可能仍留在托盘。
3. 打开修复版客户端，保留原来的数据和配置。
4. 在“运行概览”点击“查询额度”，等待一次完整查询。
5. 核对来源为真实 Codex、最近查询时间已更新。额度耗尽或达到保留线时也应显示实际百分比，派发按原条件等待。

无需删库、删除任务、重新登录、重新勾选续接授权或调低保留线。旧后台如果仍在运行，新客户端可能连接它，必须完成第 2 步。

## 修复的边界

- 完整查询的窗口时间回退不超过 1 秒时，保留历史较晚时间用于后续比较，同时按新快照判断可用性。
- 1 秒内的向前变化也不算窗口刷新，不能触发 `refresh` 调度。
- 当前窗口已到期、快照过期、缺失已知窗口、身份未知、查询失败或更大的时间回退仍保持阻断。
- 额度恢复只通过完整查询确认，不因倒计时结束或打开旧数据库恢复。
- 不修改任务、不可变运行快照、审批策略或文件权限；不会自动开启调度。

若按上述步骤仍未知，保留数据，到概览核对查询错误代码和最近查询时间。只能根据明确证据继续排查，不把所有查询故障都归因于本次 1 秒差异。
