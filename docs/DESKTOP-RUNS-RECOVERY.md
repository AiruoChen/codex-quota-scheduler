# 运行记录与异常处理

日期：2026-10-25。GUI 模块复用现有执行、取消、恢复核对与事务修复接口，不改变远端协议或自动派发规则。

## 查找记录

运行记录可按任务名称、任务/运行 ID、项目目录和状态筛选，每页 25 条，按持久化创建顺序倒序显示。
过滤与分页在 SQLite 中使用参数化查询；列表只返回元数据，不包含指令正文或运行输出。
归档、编辑、取消及重启都不会删除旧运行快照。没有匹配项时明确显示空状态。

详情显示任务版本、快照中的目录与权限、开始/完成时间、脱敏的已记录来源、准确会话/回合、错误和执行/恢复审计。
来源缺失时明确提示缺少证据，不用当前账户或最新会话代替原记录。

## 阅读与复制输出

成功记录显示最终输出；执行中、失败、取消或待核对记录中的已有内容标为已保存的部分输出。
输出可选择、复制或跳到末尾，指令快照可展开并单独复制。复制由用户触发，仅使用浏览器文本复制能力。
系统拒绝复制时提示手动选择后 Ctrl+C，不报告复制成功。

详情刷新保留输出滚动位置和展开状态，键盘焦点尽量保留在同一操作控件。
正在选择详情文本时暂缓替换内容，并提示有新状态；结束选择后显示最新已读取数据。
同一条记录的并发读取会合并。切换或关闭详情后，旧响应和旧错误会被丢弃，新详情先显示加载状态，不展示上一条内容。

请求取消后仍以数据库/远端终态为准。若取消标志仍存在而运行未结束，显示“等待准确回合终态”，不会提前显示已取消。
取消未确认的记录继续保留 needs_attention，原输出仍可查看。

## 处理异常

1. 打开“异常与恢复”，重新检查本地进程、执行权和持久化记录。界面说明每个问题及建议下一步。
2. 只有明确选择“显式修复本地遗留状态”才调用修复；服务端在同一事务重验进程。存活或无法确认退出的进程不能被自动释放。
3. 在待核对卡片查看原会话与准确回合。“只读核对”只读取已保存的来源、账户、目录和回合，不创建/续接/中断远端回合。
4. “应用已确认结果”须明确确认，再重新读取准确回合并事务校验本地记录。未确认或存在冲突时不覆盖、不重发。
5. “确认已人工核对”只解除该记录的派发阻塞；保留待核对状态和历史，队列不会自动恢复。

待核对列表采用服务端分页，包括已经人工确认阻塞、但状态仍是 needs_attention 的记录，并明确区分其阻塞状态。
审批、补充输入、未知进程和提交结果不明均不会被自动同意、解锁或重发。
模拟模式的远端核对按钮禁用，服务端也拒绝此类请求。

“本次后台会话的核对结果”显示当前后台保留的有限操作摘要：读取中、已确认终态或尚未确认。只读核对不自动应用结果。
这些会话摘要不是永久审计，重启后可重新发起只读核对；已应用结果及修复审计继续保存在运行详情。

运行 `npm.cmd run check`、`npm.cmd test`、`npm.cmd run demo`，再顺序验收打包版 `smoke-desktop.mjs` 与 `smoke-lifecycle.mjs`。

- 10000 条记录筛选分页、状态过滤、稳定顺序及列表排除正文/输出；本机筛选页约 21 ms，非所有设备的保证。
- 合并详情请求、切换后丢弃旧响应/错误、文本选择及滚动保留、真实文本复制和取消等待提示。
