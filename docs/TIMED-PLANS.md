# 定时计划与额度窗口衔接

日期：2026-10-28。适用于包含本模块的 0.4.0 源码／测试包；旧的 0.4.0 安装包不会自动增加功能。需求依据：[完整需求及 TS01–TS25](REQUIREMENTS-TIMED-START.md)。

## 普通用户：先用指定时间执行

1. 在“任务管理”准备好任务，核对指令、模型、会话、权限及最长运行时间。
2. 查询真实额度，确保顶部显示正确的脱敏账户；模拟模式只能练习草稿和预览。
3. 打开“定时计划 → 新建计划”，选择任务和版本、未来日期、时间及 IANA 时区。中国大陆通常选 `Asia/Shanghai`。
4. 选择单次或每日。每日可填写结束日期；默认不允许离线补执行，启动有效期默认五分钟。
5. 点击“预览时间线”，核对 UTC 和本机显示时间，再“保存草稿”。保存不会执行，也不会自动启用。
6. 在列表点“预览并启用”，逐项核对后勾选无人值守执行授权，再确认启用。
7. 打开“调度队列”，启动调度进程，再明确恢复派发。页面若提示“当前不会执行”，先处理它指出的阻塞。

电脑要开机，后台要存活并可连接 Codex。隐藏到托盘可以继续工作；退出、关机或休眠不能保证准时，也没有自动唤醒功能。到时仍检查真实额度、周限制、保留线、账户、模型、目录、授权和执行权，不会自动同意审批。

最晚启动时间只限制首次发送；任务一旦开始，继续使用任务自己的执行超时。已运行任务不被新计划抢占。超过有效期未发送会记“已错过”，不会在之后突然补发。

## 窗口衔接助手：先看条件

选择“窗口衔接助手”后，日期和时间指你准备开始使用的时刻 S。选择服务端实际返回的窗口长度 D，填写希望开始使用 L 分钟后自然重置，以及希望保留的额度比例。

示例：S=08:00、D=300 分钟、L=120 分钟，则预计 05:00 执行已选任务，目标重置时间为 10:00。公式为 `A = S + L − D`，不会把 D 固定为五小时。

这只是实验估算。官方接口提供窗口长度和重置时间，但没有足够依据保证所有账户都能用首次请求启动倒计时。工具不会修改服务端重置时间，也不能保证醒来时有完整额度或连续获得两份完整额度。

- 已有可信服务端边界与目标不符时，实例显示窗口冲突。调整时间或改用普通定时计划；工具不会反复发请求强制对齐。
- 首次完整可用额度没有重置时间时，只有明确确认实验与保护风险后才允许一个预触发实例。提交成功不等于对齐成功，实际边界仍需完整查询。
- 完整额度、身份或已知窗口证据未知／过期时，继续阻断；缺少可靠 D 时不能启用衔接。
- 预触发执行真实任务，会消耗额度。请自行准备短小、低影响且范围清楚的任务；工具不编造指令。
- 不会在 S 再发送另一条任务。S 附近只评估额度目标；未及时观测会显示未知。

“开始使用后继续保护多久”从 S 计算保护结束时间；保护开始于估算执行 A。例如 S=08:00、保护240分钟，对应保护05:00–12:00。保护分钟数至少覆盖 L。

保护时段内，本工具其他普通自动任务及额度续接等待；仅本次授权的预触发实例可执行。不能控制官方客户端、其他设备或其他数据库实例。已有活动任务继续，不会强制中止。

通过本工具手动执行会要求单独确认可能消耗预留额度；CLI 可显式使用 `task run ID --allow-protected` 或 `runs start ID --allow-protected`。该确认不降低原权限或额度保留线，只作用于本次运行。

## 管理与排查

列表提供编辑、预览启用、暂停计划、取消未来安排、最近实例、关联运行和复制安全诊断。

| 显示 | 含义与操作 |
| --- | --- |
| 草稿 | 尚未授权执行；预览后启用 |
| 已启用，但当前不会执行 | 调度未启动、派发暂停或服务离线；检查全局状态 |
| 到时待派发 | 已到最早时刻，等待串行领取及预检；也可能在等待其他高优先级记录 |
| 等待额度／额度未知 | 保留线、周窗口、过期或查询失败仍阻断；过期后记错过 |
| 窗口冲突 | 已有边界偏离目标；调整计划，不反复发请求 |
| 受其他计划保护 | 其他计划自己的保护尚未结束 |
| 已错过 | 默认不追赶历史；改约未来时间或使用手动入口 |
| 待人工核对 | 查看关联运行的固定字段诊断和发送证据，不自动解锁或重发 |
| 账户、来源、CLI、窗口长度或任务状态变化 | 计划暂停，撤销自身保护；核对后重新预览启用 |
| 时钟跳变 | 校准系统时间并重新核对；定时和全局派发保持暂停 |

编辑计划会变成草稿，停止未来／未领取实例并撤销自身保护，必须重新启用。任务编辑不会自动替换计划已确认的版本；在编辑计划的版本下拉框选择新版本再确认。

暂停／取消不终止已开始的回合；如需取消运行，进入运行详情单独请求，并等待准确终态。保护撤销或到期不会解除全局暂停和其他待核对阻塞。取消和队列移除都保留历史及去重证据。

实例详情把预计执行、实际开始预检、发送边界记录、目标重置、服务端实际重置及观测时间分开显示。发送边界记录不证明服务端成功；历史观测也不代表当前额度可用。

复制诊断使用字段白名单，包含计划／实例 ID、UTC 时间、固定状态、发送边界和观测结果，不含指令、原始错误、账户凭据、会话正文或私人目录。旧记录没有保存的事实不能补造。

## 时间和数据规则

- 单次／每日使用保存的 IANA 时区，不随操作系统时区改变；当地夏令时缺失时刻跳过并记录一次通知，重复时刻取首次。
- 有效期范围1–1440分钟；补执行默认关闭。允许补执行也须在有效期内，不能追赶全部历史日期。
- 每日实例按“计划 ID + 目标当地日期”唯一，计划 revision 只用于并发和授权核验。修改同日时间、取消再启用或移除队列都不能重发已消费实例。
- 普通队列仍按任务和版本去重；定时实例有独立授权身份。refresh 模式的普通队列凭据不会被定时实例消费。
- 时钟相对单调时钟跳变超过五秒，或明确向后跳变，会暂停新定时派发；到达本地时间不能生成额度重置证据。
- 计划保护冲突在启用时拒绝。每日自身保护相互重叠也需调整；没有默认允许整个任务 ID 绕过保护的机制。
- 最多1000个计划，最近列表展示至多40个实例，历史去重不自动删除。

数据库模式升级到11，新增计划、实例、定时队列及统一顺序计数，已有任务、历史、普通队列和移除标记保留。升级前安全停止旧后台并备份；不能降级让旧程序写新数据库。配置／数据迁移沿用现有备份、完整性检查和原子替换流程。

## 模块与验证

| 层 | 代码职责 |
| --- | --- |
| 领域 | `src/domain/timed-plan.ts`：严格输入、IANA 时间、DST、时间公式、最终时段判断及可注入时钟守卫 |
| 存储 | `timed-plan-repository`、`timed-records`、`timed-check`：版本快照、授权上下文、计划及实例持久化、完整性检查 |
| 调度 | `timed-dispatch`：维护与错过、保护、候选、原子领取、结果关联；现有调度仓储只合并候选，不增加第二把执行锁 |
| 执行 | CodexExecutor／ManualExecutionService 在发送前再次验证时间、计划、账户、CLI、保护和额度；提交不明不重发 |
| 界面 | 固定会话／CSRF HTTP 接口及 `schedules.ts`；不增加 Electron 权限或任意 IPC |
| 通知 | 复用既有持久化事件游标和通知偏好，仅固定摘要文字 |

`tests/timed-plans.test.ts` 覆盖计算、夏令时、授权、重复、暂停、额度、保护、错过、时钟、重启证据及10→11迁移；`execution-preflight` 使用协议替身证明最终发送边界不越过截止或暂停；管理接口测试覆盖认证和诊断隐私；桌面验收使用真实渲染器和隔离 mock 数据验证草稿、确认框及草稿保留。

完整校验使用 `npm run check`、`npm test`、`npm run demo` 及 Windows 隔离安装包验收。所有执行均为模拟或协议替身，没有消费真实账户或恢复／重发用户原任务。正式发布继续保留现有签名、真实账户独立任务、原生休眠／恢复、通知及长期稳定性人工门禁。

本工作区没有 `config/local.json`，PATH 也没有 `codex.cmd`，因此不能在这里声称已重新验证用户当前 CLI 或真实窗口行为。安装后先只读核对 `codex --version` 与额度查询，再在用户单独授权的独立任务上验证；不得拿旧任务作自动恢复实验。
