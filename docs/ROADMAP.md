# 分阶段开发路线

每次只推进约定阶段，提交代码、验证结果和剩余事项。状态必须与实际能力一致。

## 阶段 0：框架（当前）

- [x] TypeScript 严格模式、构建和跨平台测试入口
- [x] 模块边界、领域模型和接口
- [x] 配置及示例任务加载
- [x] 模拟额度、响应归一化和调度预览
- [x] README、需求、架构与开发约定
- [ ] 真实额度和真实发送属于后续阶段

## 阶段 1：真实额度读取（下一块）

入口：src/adapters/codex/app-server-provider.ts。

实现 CLI 发现与版本检查、JSON-RPC 连接、initialize / initialized 握手、
账户状态读取、account/rateLimits/read、超时、进程退出与清理。
使用当前登录凭据，不额外存储访问令牌；配置需能指定 Codex 可执行文件位置。

验收：status 返回来源 codex 的真实数据；认证失败、缺少 CLI、字段缺失和进程退出有明确错误；
模拟协议验证握手、响应匹配及超时，并完成一次本人账户只读查询。

可交给 Codex 的任务：

> 阅读 AGENTS.md 和现有架构，仅完成阶段 1。先核对官方文档与本机版本，再实现真实额度适配器。
> 保持 QuotaProvider 接口，补充必要配置和测试，完成一次只读查询。更新文档后停止，不提交真实任务。

## 阶段 2：任务与配置管理

实现持久化 TaskRepository / RunRepository、数据迁移、任务编辑命令、指令版本快照。
验收：增删改查可用，重复 ID 被拒绝，重启后定义与历史仍存在，坏数据有恢复办法。

## 阶段 3：手动执行

实现 CodexExecutor，对接 codex exec 或 App Server；明确工作目录、模型、权限和会话。
接收执行事件，支持超时与取消，保存结果。模拟来源不能用于放行真实自动提交。
验收：手动完成一个有明确范围的任务；失败、取消和需要人工处理均正确记录。

## 阶段 4：持续监控

增加轮询、更新通知、退避重试、刷新事件、唤醒后重新读取。
验收：相同快照不重复产生刷新事件；缺失窗口、周额度阻塞和时钟变化得到正确处理。

## 阶段 5：自动调度

接入持久化执行权、去重、串行队列、暂停恢复和刷新触发模式。
自动化启用前需要已完成阶段 2 的事务和阶段 3 的执行状态记录。
验收：确认额度恢复后只启动一个合适任务；重启或重复事件不会导致盲目重发。

## 阶段 6：长期运行与管理界面

补齐崩溃恢复、结果不明核对、运行日志、管理页面、本地通知、托盘及可选开机启动。
验收：完整覆盖断网、登录失效、睡眠唤醒、执行超时和手动取消的场景。
