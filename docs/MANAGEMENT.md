# 管理界面与运行包装

这是复用现有服务的本机浏览器控制台。额度、任务、快照、运行、队列与恢复数据继续使用原配置和 SQLite，
没有新增登录方式或 Codex 协议，也没有云端托管。`mock` 页面始终清楚标注模拟来源，不能执行真实任务。

## 启动与停止

需要 Node.js 22.12+。源码首次使用：

```powershell
npm.cmd ci
npm.cmd run ui
```

打开打印的 `http://127.0.0.1:8765`。首次启动若未指定配置且没有 `config/local.json`，
将从 `config/example.json` 创建个人配置；指令和运行记录保存在被 Git 忽略的本机目录。
已有配置不会覆盖或重建，损坏数据库会报错。

`npm run ui` 包含构建，前台保持运行，Ctrl+C 请求停止。已构建时可双击 `launch.cmd`，
或使用 `sh launch.sh`。启动脚本会切换到项目目录，支持路径中含空格和中文。

```powershell
npm.cmd start -- ui --config config/local.json --port 8765
npm.cmd start -- service start --config config/local.json --port 8765
npm.cmd start -- service status --config config/local.json
npm.cmd start -- service logs --config config/local.json
npm.cmd start -- service stop --config config/local.json
```

`--port 0` 自动选择空闲端口；服务命令默认使用 `config/local.json`。
后台启动隐藏子进程窗口，等待就绪后返回地址；重复 start 返回已运行的实例，不启动第二份。
关闭网页不停止服务。前台退出和后台停止都请求取消当前自有操作，并等待其实际结果保存。
若 3 秒内未完成，stop 返回 `stopping: true`，请稍后查询 status；程序不会按 PID 强杀进程。

服务只监听 `127.0.0.1`。准确地址、会话、Origin 和写请求 CSRF 校验必须匹配，不支持远程绑定或反向代理。
浏览器在服务重启后需重新加载页面，取得新的会话。

## 日常操作

1. 在运行概览查看各服务端窗口的剩余量、时间和动态。窗口时长来自查询，不固定为 5 小时。
   历史检查点过期、查询失败或字段缺失时视为未知，不依据时间倒数宣布额度恢复。
2. 在任务管理中新建任务，填写项目目录和指令，可设置启用、优先级、模型、会话、文件访问权限及超时。
   项目相对路径以配置文件所在目录解析；默认只读权限。指令直接入库，不需要先创建 Markdown 文件。
3. 保存编辑会检查 revision，过期页面不能覆盖其他修改。归档保留历史；旧队列和运行继续引用原版本快照。
4. “加入队列”只保存快照。重复加入同一任务版本返回同一记录。模拟模式允许管理队列，但不提交真实任务。
5. 使用已登录的真实配置后，可手动执行任务或指定未开始的运行快照。操作立即返回，详情定期读取持久化输出。
6. 自动运行需先“启动调度进程”，再明确“恢复队列”。每次启动进程都保持暂停；任务仅在真实额度和账户检查通过后派发。
   “暂停队列”不打断当前任务，“停止进程”请求取消当前执行；需要重新监控时点击“开启监控”。
7. 运行详情可请求取消、查看会话/回合、指令快照和事件。取消请求成功不表示已取消，终态以远端确认后的记录为准。

同一数据库的手动执行和调度仍共用执行权，不因打开多个页面而重复提交。
手动执行失败、额度等待或需要审批/补充输入等结果，以运行记录为准；后台“操作已完成”表示本地处理结束。
页面不会自动同意任何审批或输入请求。请求上限 512 KiB，超长指令会被拒绝。

## 异常与恢复

“异常与恢复”显示当前 PID、遗留权及待核对记录。只有点击修复才会调用事务内的 PID 重验。
活进程或无法确认退出的进程不会被解锁，结果不明记录不会重新排队。

“只读核对”读取原来源、原账户、原目录下记录的准确回合，不改变远端会话。
“应用已确认结果”只在证据完整时保存成功、失败或中断结果；否则保留待核对状态。
“确认已核对”要求人工检查会话和文件变更，只解除调度阻塞，保留原状态；之后仍需明确恢复队列。

如果服务被系统强制结束：

```powershell
npm.cmd start -- service status
npm.cmd start -- service recover
npm.cmd start -- ui
```

recover 只在确认记录的进程已退出时清除服务实例文件，不处理数据库执行权。
进入界面后继续修复和核对数据库记录；不会自动恢复队列或重发任务。
PID 被复用或权限不足时保守拒绝恢复；损坏的实例文件也不会被自动覆盖。
数据库恢复详见 [异常与重启恢复](RECOVERY.md)。

## 配置与日志

配置页显示当前活动配置，保存通过原 ConfigManager 的校验、锁、备份和原子替换。
先停止调度并等待执行或核对结束，再修改配置。界面提示“存在待重启配置”时，停止并重新启动服务使修改生效；
修改 provider、数据库或连接设置不会切换正在运行的服务。CLI 在界面外修改的配置也需要重启。

按配置路径摘要隔离服务数据：

```text
.runtime/<配置路径摘要>/
  instance.json       当前实例 PID、地址及本机控制密钥
  runtime.log         最新事件日志
  runtime.log.1..3    轮转历史
```

该目录位于配置文件目录的上一级。日志每份约 1 MiB，最多保留当前文件和 3 份历史。
只记录固定事件和错误代码，不写提示词、任务输出、账户或个人路径。完整运行输出在 SQLite 的运行详情中。
`service status` 与 start 的输出不会包含控制密钥；此密钥与 Codex 登录凭据无关，不要提交本地运行目录。
启动失败时先以前台 ui 运行查看明确错误；端口占用不会自动更换或终止其他进程。

## 便携目录

```powershell
npm.cmd run package
```

输出 `.release/codex-quota-scheduler/`，包括运行代码、静态页面、示例配置/任务、文档和启动脚本。
可以复制或自行压缩整个目录，在目标机器上使用 `launch.cmd`、`sh launch.sh` 或 `npm run ui`。
目标机器需要 Node.js 22.12+；无需 TypeScript、node_modules 或 npm install。
真实功能还需安装 Codex CLI、使用 ChatGPT 账户登录，并在个人配置中设置 provider=codex。

生成过程仅复制白名单文件，不包含个人配置、数据库、日志、真实指令或登录资料。
重新打包会替换生成目录；检测到个人配置、数据库或运行目录时会拒绝覆盖，先备份并移走数据再构建。
建议先复制到其他位置运行，个人数据另行备份。
运行代码根据当前源码逐个选择，不复制 dist 中的孤立产物或额外 JSON 文件；打包前检查输入完整性并拒绝重定向输出的符号链接。

实例写入使用 `instance.json.lock` 串行保护创建、状态变更和显式恢复。正常操作后自动释放；
若进程恰在写入期间崩溃，锁会保留，启动/恢复报告 `RUNTIME_BUSY`，不会自动抢占。
应先核对锁中的 PID、实例记录及相关启动/停止/恢复进程，确认都已退出，备份本地运行记录后人工清理该锁，再运行 `service recover`。
不要在进程仍运行时删除锁；服务实例恢复仍不会自动清除数据库执行权或重新派发。

当前运行包装包含前台/后台进程和跨平台启动脚本。系统托盘、原生通知、开机启动、系统服务注册及安装器尚未实现。

## 验证

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run demo
npm.cmd run package
```

自动化覆盖本机接口保护、请求大小、任务版本/快照、模拟阻断、真实协议替身下的调度和取消、
过期额度、停止等待结果不明、实例锁、后台 CLI 生命周期、异常恢复及无运行依赖的便携包。
Windows 使用 Chrome 无头浏览器完成桌面 1440×1000、窄屏 390×844 与实际表单操作验收；
本模块未发送真实 Codex 任务，真实接入能力沿用已验收的执行、监控和恢复模块。
