# 分阶段开发路线

每次只推进约定阶段，提交代码、验证结果和剩余事项。状态必须与实际能力一致。

- [x] 配置及示例任务加载
- [x] 模拟额度、响应归一化和调度预览
- [x] README、需求、架构与开发约定
- [x] 模拟能力与真实能力明确分离

## 阶段 1：真实额度读取（已完成）

- [x] CLI 发现、版本检查与标准 npm Windows 启动器解析
- [x] JSON-RPC 连接、initialize / initialized 握手、请求匹配
- [x] 账户状态读取、account/rateLimits/read、来源与版本标识
- [x] 超时、进程退出、协议错误分类和子进程清理
- [x] 自定义可执行文件、前置参数、Codex home 与超时配置
- [x] 模拟协议测试及本人账户只读实测

模拟协议验证握手、响应匹配及超时，并完成一次本人账户只读查询。

使用方法和错误代码见 [真实读取说明](CODEX-QUOTA.md)。

验收：增删改查可用，重复 ID 被拒绝，重启后定义与历史仍存在，坏数据有恢复办法。

- [x] SQLite 任务/运行仓储及事务，v1 到 v2 数据迁移

- [x] 历史定义、指令快照、SHA-256 与 queued 运行记录持久化
- [x] JSON 配置初始化、校验保存、写锁、原子替换和有效备份恢复
- [x] 数据库完整性检查、快照备份及切换备份读取
- [x] 独立 CLI 进程重启、并发冲突、回滚、迁移和损坏数据测试

使用方法见 [持久化管理说明](PERSISTENCE.md)。准备运行记录不会提交 Codex 任务。

## 阶段 3：手动执行（已完成）

实现 CodexExecutor，对接 codex exec 或 App Server；明确工作目录、模型、权限和会话。
接收执行事件，支持超时与取消，保存结果。模拟来源不能用于放行真实自动提交。
验收：手动完成一个有明确范围的任务；失败、取消和需要人工处理均正确记录。

- [x] App Server 手动执行、会话续接、实际工作目录与模型/推理设置
- [x] 同连接账户/额度检查、mock 来源阻断、只读和工作区写入权限
- [x] 持久化会话/回合 ID、筛选后的事件和最终/部分输出
- [x] 任务超时、Ctrl+C、跨进程取消与中断确认
- [x] 审批/补充输入转 needs_attention，不自动授权
- [x] 原子创建并取得执行权、禁止重复启动、遗留执行权人工恢复
- [x] 模拟协议验证及本人 Plus 账户真实短指令验收

2026-10-19，Windows / Codex CLI 0.163.0-alpha.10.2：只读任务成功返回固定文本，
状态、最终输出、会话、回合与事件已落盘。个人验收数据仅存于 .local。
操作说明见 [手动执行](EXECUTION.md)。

## 阶段 4：持续监控（下一块）

增加轮询、更新通知、退避重试、刷新事件、唤醒后重新读取。
验收：相同快照不重复产生刷新事件；缺失窗口、周额度阻塞和时钟变化得到正确处理。

## 阶段 5：自动调度

接入持久化执行权、去重、串行队列、暂停恢复和刷新触发模式。
自动化启用前需要已完成阶段 2 的事务和阶段 3 的执行状态记录。
验收：确认额度恢复后只启动一个合适任务；重启或重复事件不会导致盲目重发。

## 阶段 6：长期运行与管理界面

补齐崩溃恢复、结果不明核对、运行日志、管理页面、本地通知、托盘及可选开机启动。
验收：完整覆盖断网、登录失效、睡眠唤醒、执行超时和手动取消的场景。
