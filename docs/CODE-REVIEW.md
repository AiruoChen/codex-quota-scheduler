# 代码审查记录

## 发现与修复

| 优先级 | 发现 | 修复与验证 |
| --- | --- | --- |
| P1 | 未识别的远端回合状态被当作普通失败，不能表达结果未知 | 仅明确 failed 写失败，未知状态保留 needs_attention；覆盖启动响应与完成通知两种路径，禁止重新启动同一记录 |
| P1 | 多个恢复进程的“核对再删除”之间可插入新实例创建 | 创建、保存、释放和恢复共用文件写锁；锁冲突时原记录不变，异常锁不自动清理 |
| P2 | 管理层重算额度，把缺失窗口、边界回退或身份未知覆盖为可用 | 展示仓储的保守判断；模拟时钟验证三种情况及过期数据 |
| P2 | 手动操作检查与登记之间存在 await，两个请求都能被接受 | 检查与登记放入同一同步步骤；并发请求只能登记一个后台操作。原数据库执行权仍提供第二层互斥 |
| P2 | 服务停止等待 HTTP 排空时，尚未读完的请求仍可写入 | 同步关闭操作入口并取消后台工作；回归验证慢请求被拒绝，数据库中不出现晚到任务 |
| P2 | 完整消息及被最终回答隐藏的消息绕过累计输出限制 | 按全部保留文本字节和消息数量限制；超限保留待核对，后续输出不再追加 |
| P2 | 运行控制信任任意成功 JSON 响应 | 状态验证实例 ID、PID 和字段类型；停止前先读取验证，错误身份不会收到停止 POST |
| P2 | 打包递归复制 dist，带入删除源码后残留的代码和额外文件 | 根据当前源码选取编译产物；用孤立 JS/JSON 哨兵验证排除，保留便携包异地启动验证 |
| P2 | 异步按钮结束时直接启用，覆盖分页/模式限制；旧详情响应可覆盖新选择 | 区分业务禁用与请求忙碌，列表和详情仅应用最后一次请求 |
| P3 | 执行协议位于编排层；JavaScript 未纳入 check；文档阶段过时 | 协议移入 adapters/codex；增加脚本语法和领域/调度依赖检查；更新 README、架构和路线图 |

先用六个定向用例复现原有失败，再修复并复验。新增测试只使用临时数据库、模拟时钟及本机协议替身，不提交真实指令。

## 维护建议与验证边界

1. 页面脚本目前为原生 JavaScript，语法检查不等同于类型检查。后续可按额度、任务、运行详情、配置视图拆分模块，并引入类型检查；本轮只调整明确有问题的交互，避免大范围改写。
2. 恢复报告会扫描历史记录；长期运行产生大量数据后，应补充数据量基准及增量查询，暂未给出容量或性能保证。
3. 配置和实例写锁遇到进程崩溃会保留，需确认进程退出后人工处理。这样避免不明状态下的自动抢占；操作步骤见 MANAGEMENT.md。
4. 本轮验证代码约定和可测试的安全行为；未重新消耗真实账户额度，也未重跑真实 Codex 端到端执行或 Linux 环境。测试通过不能保证所有未来协议、网络或进程崩溃组合绝无错误。
