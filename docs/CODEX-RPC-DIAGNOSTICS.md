# Codex RPC 错误诊断与续接兼容检查

本次修复改进错误分类、运行审计和脱敏诊断，并提供独立只读检查命令。它不代表任意桌面会话已经能恢复，也不实现 0.4.0 规划中的完整环境接入。

## 用户如何查看错误

打开失败运行的“查看详情”，查看错误中的请求方法、RPC 编号、分类和诊断编号；在“执行与恢复审计”中查看 `codex_rpc_error` 事件。设置页的“导出脱敏诊断”包含最近十条 RPC 错误事件中的有效白名单诊断。

每条诊断只允许以下字段：`format`、`diagnosticId`、`method`、`stage`、`rpcCode`、`reason`、`cliVersion`。请求方法及阶段使用固定枚举，版本必须符合限定格式；导出时再次验证并只复制这些字段。不记录原始服务端错误、`data`、`cause`、请求参数、凭据、账户、任务正文、会话名称或完整私人路径。诊断编号用于关联错误与事件，不是任务或会话 ID。

| 分类 | 所需证据 | 处理边界 |
| --- | --- | --- |
| `authentication_required` | 服务端认证编号或明确认证拒绝消息 | 核对登录及来源，不自动重登 |
| `method_unsupported` / `invalid_parameters` | RPC -32601 / -32602 | 核对对应 CLI 协议 |
| `thread_history_missing` | 明确的历史不可用消息 | 只读核对准确会话，不猜另一个会话 |
| `thread_archived` / `thread_closing` | 明确的归档／关闭消息 | 不自动取消归档或重试恢复 |
| `capability_required` | 明确要求 experimentalApi 的消息 | 不自动开启实验能力 |
| `history_paging_required` | 明确要求历史分页接口的消息 | 核对分页能力，不能仅凭 paginated 格式认定失败 |
| `permission_parameters_conflict` | 明确报告 permissions 与 sandbox 互斥 | 核对参数，不扩大文件权限 |
| `initialization_required` | 准确的未初始化／重复初始化消息 | 核对握手 |
| `network_failure` | 明确的网络请求失败消息 | 不再把其他错误中偶然出现的网络词语判为网络故障 |
| `unknown` | 没有匹配的明确证据 | 保持未知；单独的 -32600 不证明具体根因 |

以上分类表示服务端报告的情况，不构成自动重试、审批或释放执行权的授权。运行在提交前失败仍按原规则处理；进入提交步骤后结果不明仍为 `needs_attention`。失败运行及原快照不会被此修复自动重发。

## 独立只读检查

在源码目录中运行，参数使用客户端当前配置文件和需要检查的准确运行 ID：

```powershell
npm.cmd run diagnose:resume -- --config "配置文件的完整路径" --run "准确运行ID"
```

此命令需要维护者的源码环境；普通用户可以提供客户端导出的诊断 JSON。源码修复不会自动替换已安装客户端，应在验证后按原升级流程构建和安装对应版本。

检查程序以 SQLite `readOnly` / `query_only` 读取这条运行及已记录来源，不调用会初始化数据库或执行迁移的业务仓储。来源、账户或目录不一致时停止；缺少已记录来源时也不猜测目标。

对真实 Codex 只发送 `initialize`、`initialized`、`account/read`、`thread/read`、`thread/turns/list` 和 `thread/items/list`。历史列表仅用于判定响应结构，不根据其中的新旧回合选择恢复目标；存在准确已记录回合时，条目查询限定该回合。不输出或保存历史正文。

报告只有固定字段和布尔结果，明确包含：

- `resumeVerified: false`：本命令从不调用 `thread/resume`，没有验证实际恢复成功。
- `permissionsVerified: false`：读取基础元数据和历史不等于验证完整有效权限。
- `result: read_only_checks_passed`：仅表示原来源、账户、目录及相应读取接口检查通过。

某个读取接口不可用也不能反向证明 `thread/resume` 一定不可用。该独立命令不作为执行放行开关，不改变原任务或调度状态。

查询前后核对账户。不会恢复、创建、修改、中断或重发会话，不更新运行、调度或执行权，也不将读到的历史当作已恢复结果。底层 CLI 自身可能维护连接日志或缓存；这不属于向原会话发送任务。

## 本机协议核查与已知限制

2026-10-27，针对所配置的 Codex CLI `0.164.0-alpha.11.1` 重新生成对应 JSON Schema：`thread/resume` 的必填字段为 `threadId`；当前使用的 `excludeTurns`、`cwd`、`approvalPolicy`、`approvalsReviewer`、`sandbox` 均存在，使用的枚举值在该 Schema 中。核查未发现仅凭这些字段就必须开启全部实验能力的依据。

官方说明见 [App Server](https://learn.chatgpt.com/docs/app-server)：使用准确 `thread.id` 恢复，`excludeTurns: true` 避免返回整段历史，历史查询使用分页接口。协议结构符合并不能证明特定会话能恢复；会话状态、有效权限和实际历史装载仍可能造成其他拒绝。

既有真实失败记录只保存了通用拒绝码，详细消息没有保留，不能通过本次更新回补根因。真实只读报告与对应 Schema 检查只能缩小范围，不能替代实际恢复验证；本阶段保持原问题的具体拒绝原因为未知。

本次执行结果：`npm run check`、`npm test`（288 项）及 `npm run demo` 全部通过。新只读入口在上述真实 CLI 上确认原记录的来源、账户、目录、会话元数据及两类历史读取接口可用，历史模式为 paginated；目标运行、执行事件、执行权及调度控制状态的检查前后摘要相同。报告保持 `resumeVerified: false`、`permissionsVerified: false`，没有恢复或重发原任务。真实检查报告仅保存在本机被忽略的数据目录，不提交账户或会话标识。

## 后续真实验证步骤

1. 使用匹配源码构建的版本，保留旧失败记录及用户数据备份；先检查固定字段诊断和上述只读报告。
2. 核对准确会话、完整执行环境、账户和活动任务；审批、权限、暂停及恢复约束继续有效。
3. 如果需要实际 `thread/resume`，单独取得明确授权，提前界定是否只恢复连接、是否允许发送新指令，以及可能触发的会话状态或初始化变化。本次修复与检查未授权或执行这一步。
4. 一次受控尝试后，使用新诊断编号与固定类别定位服务端拒绝；仍为 `unknown` 就继续保持未知，不能通过自动重试、改变会话或扩大权限绕过。

模拟回归覆盖明确类别、未知错误、敏感内容混入、坏诊断字段、导出白名单、只读目标与来源检查、恢复拒绝不提交及提交结果不明不重发。`check`、`test`、`demo` 的结果以本次执行报告为准。
